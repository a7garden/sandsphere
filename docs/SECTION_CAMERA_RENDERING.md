# Sandsphere 단면 카메라 렌더 명세

2026-10-10 최신 개선: [표면 확대·회전·경계 검증](SECTION_REDESIGN_VALIDATION.md). 기본 진입은 표면 확대이며 두 축 회전, 이동, 전체 단면 전환을 같은 canvas에서 제공한다.

2026년 10월 10일 설계 개정. 이 문서는 렌더 계약이다. 현재 P1 수정과 첫 실시간 단면 구현의 범위·실행 근거·남은 확장은 [구현 및 검증](IMPLEMENTATION_VALIDATION.md)에 기록했다. 확정 요구는 같은 시뮬레이션 canvas에서 구형과 단면을 연속 전환하고, 단면에서도 현재 게임의 모든 렌더 레이어와 도구를 실시간으로 사용하는 것이다. 계산 모델과 열·시간 정책은 [전체 설계](SCIENCE_SECTION_DESIGN.md)를 따른다.

## 1. 씬과 상태의 소유권

`PlanetView`의 기존 engine·scene·canvas·render loop를 유지한다. 화면마다 solver나 물리 입자를 추가하지 않는다. 실행 순서는 공통 tick → 커밋 → 공통 지형·입자 frame → 카메라/절단 상태 → 한 번의 scene render다. 구형에서 단면으로 넘어가는 사이에도 이 순서가 계속된다.

```text
                     공통 simulation controller
                  state / tick / commands / stock
                            │
                   geometry · falling · events
                            │
                         PlanetView
                 ┌──────────┴──────────┐
              구형 카메라          단면 카메라
                 └──────────┬──────────┘
                  같은 scene와 canvas의 렌더
                            │
                   같은 도구·선택 셀·관측
```

전환은 표시 상태다. `resume()`, `solver.replace()`, `snapshotSurface()`, `clearGrains()`, `settleGrains()`, 명령 큐 초기화, 비활성 행성으로의 이동을 호출하지 않는다. 기존 pause와 speed를 그대로 유지한다. 돌아갈 카메라 상태, 절단 기저·확대는 표시 설정으로 저장할 수 있다.

실제 질량을 가진 공급 입자와 질량 없는 증기·강수·열 효과를 구분한다. 전자는 공통 simulation에서 한 번만 진행·착지·탈출하고, 후자는 같은 사건에서 한 번 생성해 수명을 유지한다. 카메라 변경은 어느 쪽도 새로 생성하는 사건이 아니다.

## 2. 절단 공간과 카메라

행성 로컬 좌표에서 정규직교 기저 u,v,n을 만들고 `n=u×v`로 둔다. 중심 평면은 `dot(n,x)=0`이다. 기본 진입은 현재 선택 표면 p와 카메라의 접선 t에서 `v=p, u=t, n=u×v`를 구성한다. 북극과 접선 길이 0 근처에서 다른 카메라 축을 사용한다. 전체 대원 경로는 `d(phi)=u cos(phi)+v sin(phi)`다.

최종 카메라는 n 방향에서 평면을 보며 화면의 오른쪽과 위는 u,v다. 직교 투영에서 이동·확대가 가능하고, 첫 framing은 선택 표면 주변을 보여준다. 축소하면 원형 단면 전체가 보인다. 행성의 곡률을 유지하고 중력은 모든 위치에서 행성 중심을 향한다. 별도 평면 세계나 아래 방향의 2D 중력을 만들지 않는다.

절단 표시 띠는 `abs(dot(n,x)) <= halfWidth`다. halfWidth는 원래 셀의 대표 각폭에 대응하는 초기값에서 조정한다. 실제 격자 해상도·두께·질량을 변경하지 않는다. 확대만으로 띠 폭이나 관측 셀 집합을 바꾸지 않는다. 띠 밖에서도 원래 구면 물리와 물질 교환은 계속된다.

드래그의 가로 성분은 v 축 주변에서 u를 회전하고, 세로 성분은 갱신된 u 축 주변에서 v를 회전한다. 매번 정규화해 n=u×v를 재계산한다. 각도 출력은 이 로컬 축 조작의 누적각이며 위도/경도를 의미하지 않는다. 화면 이동은 기저의 두 좌표로 별도 보관하므로 절단 법선을 바꾸지 않는다. 두 손가락 중심 이동은 공통 입력 경로에서 한 번만 적용한다.

표면 framing은 선택 방향의 표시 반지름에서 0.15 아래를 중심으로 초기 수직 반폭 1.35를 사용한다. 회전하면 현재 방향의 표면 높이를 따라간다. 전체 framing은 중심을 0으로 되돌리고 표시 고도의 상한까지 화면에 들어오도록 맞춘다. 전체/표면 framing의 중심·이동·확대는 0.12초 시정수로 보간하며 reduced motion에서는 즉시 적용한다. 홈은 현재 절단 방향을 유지하면서 표면 framing으로 복귀한다.

root의 자전·기울기 변환 R에 따라 세계 좌표 기저는 Ru,Rv,Rn으로 갱신한다. 카메라와 clip은 같은 변환을 사용한다. 태양 방향과 공전 환경은 기존 계산 결과를 읽는다. 단면에 들어왔다는 이유로 자전이나 낮·밤을 멈추지 않는다.

전환 controller는 현재 pose와 projection, 절단 표시의 진행률을 함께 보관한다. 목표까지 움직이는 도중 재전환하면 현재 pose에서 반대 방향으로 진행하며 최초 상태로 순간 이동하지 않는다. 구형의 원근 투영과 단면의 직교 투영 사이에서는 화면 크기가 연속적으로 이어지는 투영 경로를 사용한다. 단순 `camera.mode` 전환으로 생기는 크기 점프를 완료로 인정하지 않는다. 보간 행렬은 유효한 near/far clipping과 역변환을 유지해야 한다.

전환 중의 그림도 기존 render loop에서 그린다. 초기 전환 시간은 약 300ms를 시작값으로 검토하며 조작·성능 평가로 확정한다. reduced motion은 같은 마지막 카메라·절단 상태로 바로 이동한다. 양쪽 경로에서 진행한 물리 tick은 같아야 한다.

## 3. 공통 형상과 절단 면

현재 `PlanetView.update()`의 표면 메시만 잘라서는 내부가 비어 보인다. 별도의 잘린 면을 만들어 같은 씬에 붙여야 한다. 절단 mesh는 원래 셀 상태를 표현하는 렌더 캐시이며 물리 상태나 충돌체가 아니다.

두 모드가 같은 `SurfaceGeometryFrame`을 사용한다. 원래 셀의 baseHeight, solidTop(얼음 포함), hydraulicHead, 액체 물·보유수·얼음량, 표시 반지름, owner cellId를 커밋마다 계산한다. 물리 경계는 solver 값, 장면 형상은 양쪽에서 동일한 높이 압축 함수로 얻는다. 단면의 수치 표시에는 압축 전 높이를 쓴다. 원래 구형의 해안 보간은 장식용 경계임을 구분하고 물리 접촉 경계를 대체하지 않는다.

현재 구형 렌더는 얼음을 고체 높이에서 빼 물과 함께 표현하고 토양 보유수를 수심에서 뺀다. 이 차이는 공유 geometry 정리에서 해결한다. 단면만 다른 기하 경계를 그려 겹치는 물방울·수면·얼음이 전환 중 튀게 만들지 않는다. 각 셀의 고체와 물에 대한 물리 접촉과 표시 투영의 차이도 같은 계약으로 처리한다.

절단 mesh는 원래 셀의 기둥 경계와 띠의 교차에서 생성한다. 고체는 기반에서 solidTop까지, 물은 solidTop에서 hydraulicHead까지다. 각 primitive에 owner cellId를 유지해 picking과 관측을 원래 셀로 돌려보낸다. 비인접 셀을 보간으로 이어 새 수로나 벽을 만들지 않는다. 기반 내부는 고정 영역으로 표시하고 편집할 물질량으로 집계하지 않는다.

조성은 현재 셀량을 반영한 혼합 재질·입자 무늬로 표현한다. 무늬의 seed는 cellId와 materialId에 고정하고 전환마다 바꾸지 않는다. 실제 공급 중인 낙하 입자와 정착 물질의 시각 무늬를 구분한다. 현재 모델은 층 순서가 없으므로 모래 위에 점토, 그 아래 유리와 같은 가상 지층을 생성하지 않는다. 대표 온도는 그 셀 전체의 값이며 색으로 임의의 지하 온도장을 그리지 않는다.

잘린 면은 시야 앞쪽 경계에 배치하되 경계 offset은 렌더 오차 방지용이다. 그 offset을 낙하 충돌이나 명령의 3D 위치로 사용하지 않는다. depth·법선·backface·수면 경계·열 overlay가 기존 표면과 맞아야 한다. 중심 평면에 생기는 절단 면이 새로운 물리 벽으로 작동해서는 안 된다.

## 4. 모든 렌더 레이어의 연결

| 현재 경로 | 단면에서의 처리 | 공통 상태와 주의점 |
| --- | --- | --- |
| `planet.ts`, `materials.ts`, `surface.ts` | 구면 메시 clip + 고체 절단 mesh와 혼합 재질 | 모래·점토·도자기·유리·소금·용융·암석·토양·운철·얼음의 현재 셀량. 기존 색·거칠기·열 효과 유지. |
| 물 메시와 water shader | 같은 수면과 물의 절단 면 렌더 | 액체 물과 얼음의 상 구분, 보유수 중복 없음. shader time은 공통 게임 시간. |
| `particles.ts`, 공급 grain instances, 물 stream | 같은 입자 ID·위치·속도·물줄기를 clip해서 표시 | 질량을 가진 입자의 수는 모드와 무관. 띠 밖의 입자가 들어오면 기존 수명·궤적으로 나타남. |
| `effects.ts` | 증기·가열·기체 공급·탈출 tracer를 같은 사건·수명으로 표시 | 장식 입자 수를 kg으로 해석하지 않음. 전환은 emit 사건 아님. |
| `sky.ts` | 같은 대기 조성·밀도 texture와 조명으로 절단 띠의 대기 표시 | 원근/직교의 ray 생성과 ray 적분 구간을 수정. 단면의 실제 수직 상태를 새로 만든 것으로 표시하지 않음. |
| `cloudBanks.ts`, `cloudComposition.ts` | 같은 cloud·cloudIce를 가진 구름 chunk·면·밀도 렌더를 절단 | 모든 선택 가능한 구름 표시 방식 지원. 원근/직교 ray, instance 좌표, clip과 chunk 절단 면 처리. |
| `weather.ts`, `precipitationLayer.ts` | 같은 비·눈 stroke, 강수 셀 강조를 단면에 대응 | 강수는 solver가 한 번 이동. 장식 drop의 수명 유지. mesh 위치만 보고 잘못된 셀에 집계하지 않음. |
| `biosphere.ts`, `vegetation.ts` | 같은 식생·나무·초식·육식 표시를 띠 안의 표면에서 렌더 | 생물량은 실제 셀 필드. 나무·개체 모양은 같은 대표 표현이며 새 개체 물리 생성 아님. |
| heatSurface와 열 색 | 현재 온도·소성·용융/응고 변화를 절단 면에도 표시 | 같은 대표 온도와 반응 결과. 유량·반응열 추정으로 가짜 화살표를 만들지 않음. |
| `meteor()`의 운석과 trail | 같은 비행을 표시하고 같은 충돌 명령 수행 | 전환 중 Promise나 애니메이션을 새로 시작하지 않음. 충돌은 한 번. |
| 선택 셀·브러시·축·측정 | 단면의 동일 셀과 실제 공급 목표를 표시 | 모드별 picking 결과는 하나만 명령 controller에 전달. |
| 태양·우주 배경 | 현재 조명과 배경 유지 | 행성의 절단 띠를 태양과 전체 배경에 적용하지 않음. |

‘전체 렌더’는 모든 물질·현상 유형을 지원한다는 의미다. 띠 밖의 행성 전체 입자를 단면에 중복 투영해 물질이 늘어난 것처럼 그리지 않는다. 관측 대상 셀의 열·물·생물·기체 변화를 생략하거나 정지 그림으로 대체하지 않는다.

`materials.ts`, `sky.ts`, `cloudBanks.ts`는 custom ShaderMaterial을 사용한다. scene의 clip 설정 하나로 전부 잘릴 것이라고 가정하지 않는다. 공통 clip uniforms와 정규화한 signed distance를 각 shader에 연결하고, thin instance의 최종 world 위치를 포함한다. StandardMaterial·ParticleSystem·LinesMesh 경로도 실제 절단 결과를 각각 검사한다. clip 대상은 행성 렌더에 한정한다.

현재 대기 shader는 `normalize(vLocalPosition-cameraLocal)`, 구름 밀도 shader는 `normalize(localPosition-localEye)`로 원근 ray를 만든다. 직교 카메라에서는 픽셀별 origin과 공통 방향이 필요하다. 두 shader 모두 공통 inverse view-projection에서 올바른 ray를 생성하도록 수정한다. 대기·구름의 ray 적분도 절단 띠와 교차하는 구간에 제한해야 한다. 표면 fragment만 discard하면 뒤쪽 대기·구름이 계속 적분되는 문제가 남는다.

깎인 구름 chunk의 내부가 검은 빈 공간으로 보이지 않게 밀도 ray 또는 절단 mesh를 처리한다. 수면 뒤의 입자, 불투명 고체 뒤의 증기, additive 열 효과가 depth를 무시하고 앞에 나타나지 않도록 rendering group별 depth·alpha 정책을 검증한다. 기존 레이어 토글·테마·표면 표현 설정은 두 카메라에 동일하게 적용한다.

## 5. 단면에서의 도구와 위치

단면의 screen ray를 행성 로컬 좌표로 바꾼다. 평면 교점은 `tau=-dot(n,origin)/dot(n,direction)`이다. 분모가 작은 경우, 교점이 카메라 뒤인 경우, 행성 중심처럼 방향이 정의되지 않는 경우를 처리한다. 전환 중에는 현재 투영의 유효한 picking을 사용하고 기존 획의 목표는 유지한다. GPU clip은 CPU picking의 보장 조건이 아니므로 보이지 않는 메시 hit를 걸러야 한다.

고체·물 절단 mesh의 primitive owner는 실제 cellId다. 원래 구면의 같은 셀을 선택해도 같은 값과 명령을 얻는다. 단면의 깊이 위치를 새로운 물리 셀로 만들지 않는다. 기둥 안에서 가열하면 현재 모델의 해당 기둥 대표 온도에 적용한다. 고정 기반·중심은 편집 대상이 아니며, 커서는 가능한 대상과 공급 시작점을 구별해 보여준다.

공기 영역에서 붓기를 시작하면 커서의 평면 좌표를 행성 로컬 3D emitter 위치로 전달한다. 고체 안에서 시작하면 해당 표면 경계의 공급 위치를 보여준다. 공급량·위치·초기 속도·물질·targetTick은 한 명령 payload로 확정한다. 단면이 보기 편하도록 실제 낙하 궤적을 평면에 강제로 가두거나 다시 시작하지 않는다.

현재 `PlanetView.emit()`는 공급 위치의 접선에 `camera.upVector`를 사용한다. 이 계산을 공급 명령을 생성하는 controller로 옮기고 확정한 로컬 위치·속도를 simulation에 전달한다. 전환 중 camera.up을 바꾸어 이미 결정한 공급 위치나 속도가 바뀌지 않아야 한다. grain의 렌더 변환은 해당 공통 상태를 읽기만 한다.

붓은 원래 구면 `brushWeights`를 재사용하며, 단면의 픽셀 수나 절단 mesh 수에 비례해 공급량을 늘리지 않는다. 기체 공급, 가열·냉각·깎기·회수, 운석은 기존 command controller로 전달한다. 동일 셀을 단면과 구형에서 편집한 비교 실험은 명령 내용이 같으면 결과도 같아야 한다. 단면의 폭이 브러시보다 좁다면 실제 영향을 받는 표면 범위를 커서와 셀 관측으로 알린다.

## 6. 구현 순서와 출시 기준

| 작업 | 산출물 | 다음 작업으로 넘어가는 근거 |
| --- | --- | --- |
| 공통 상태 정리 | 낙하 step과 emitter payload, 지형 경계, 커밋 frame | 렌더 빈도·카메라 up·mode가 질량과 궤적을 바꾸지 않음. |
| 카메라 전환과 절단 면 | 같은 canvas에서 pose·projection·clip 전환, 고체·물 cap, owner picking | 전환 중 프레임을 비우지 않음. 현재 상태에서 역전환 가능. 구형 복귀 확대·대상 보존. |
| 레이어 연결 | 위 표의 모든 렌더 경로와 도구 | 각 경로의 실제 비영 상태에서 렌더·입력·occlusion 확인. 전체를 연결하기 전에는 출시 완료로 처리하지 않음. |
| 출시 검증 | 같은 세계의 A/B 비교, CPU/WGSL, GPU fallback, 입력·성능 | 아래 필수 장면과 상태 검증 통과. |

필수 장면은 물·고체 공급 중 반복 전환, 단면의 가열·냉각·소성·유리화, 비·눈·구름·증발·기체 탈출, 식생·먹이망, 회수·재공급, 운석 충돌이다. 현재 모델에 없는 재용융·용융 유출은 물리 기능을 추가하는 단계에서 같은 비교에 포함한다.

동일 초기 상태와 같은 tick별 명령열에서 ‘전환 없음’과 ‘10회 반복 전환’의 solver state, 낙하 ID·위치·속도·질량·착지 사건, 명령 순서, stock·공급·회수·탈출 장부를 비교한다. 정지와 1/2/4배속, 자전·기울기, GPU readback 진행 중에도 검사한다. 화면 표현 RNG가 물리 RNG 순서를 소비하지 않아야 한다.

화면 검증은 카메라 전환의 연속 point trajectory, 원근↔직교 크기·clip jump, 줌·pan·picking, 투명도·depth, 파도·구름·입자 수명의 연속성, 각 레이어 토글, 375/768/1440px, 키보드·터치·reduced motion을 포함한다. 프레임 비용은 동일 상태에서 모드별 steady-state와 전환 중 각각 측정한다. 테스트가 통과하기 전에는 ‘실시간 단면 완성’이라고 표시하지 않는다.

## 7. 공유 경계와 고정 기반의 표현

고체 상단은 구면에 사용한 실제 삼각형의 절단 교점이다. 기반 경계의 높이는 같은 렌더 정점의 기반 높이를 교점의 edge weight로 보간한다. 이웃 삼각형의 물질 owner가 달라도 공유 변의 교점과 기반 높이는 같다. 해안의 실제 inset·급경사와 물질 소유권은 유지한다. 기반이 표현용 해안 보간보다 높아질 때 상단에서 제한해 뒤집힌 고체 띠를 만들지 않는다.

액체 바닥은 절단 평면에 생긴 실제 지형 polyline과 액체 교점 방향의 교차로 정한다. 셀별 고정 solidRadius를 반복해 만든 계단 경계를 제거한다. 지형 교차가 없는 기존 외부 호출은 기존 반지름 fallback을 지원한다. 이 재구성은 표시 좌표에만 적용하며 질량·열·압력·기둥 높이 원자료를 수정하지 않는다.

깊은 내부의 fan은 owner=-1인 편집 불가 기반이다. 중립 색상과 약한 정적 질감으로 채우며 열 색·강수색·맨틀/핵 층을 부여하지 않는다. 실제 표면 기둥의 혼합물과 기온만 기존 상태에서 읽는다. 내부 가열·굴착·대류는 이번 구현의 물리 기능이 아니다.


## 2026-10-10 기본 관찰 방식 변경

기본 단면은 국소 셀 범위를 수평으로 펼치고 기반암을 숨긴다. 물리 상태는 구면에 유지하며 표면 혼합물과 액체·대기·입자 렌더를 동일 변환으로 표시한다. 세부 구현과 최신 검증은 [펼친 단면 검증](FLAT_SECTION_VALIDATION.md)을 참조한다. 이전의 원형 전체 단면 설명은 과거 설계 기록이다.
