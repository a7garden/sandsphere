# 장시간 기후·생태 감사 — 2026-10-11

장시간 CPU 실행, 실제 브라우저의 WebGPU/CPU 교차 재개, 구면·평탄 단면의 관측값을 확인했다. 이번 감사에서 발견한 3건을 수정했다. 검사한 조건에서는 음수 질량, 비유한 값, 속도 폭주, 기체·구름의 단일 셀 붕괴를 발견하지 않았다. 아래 시간은 현실 시간이 아니라 게임의 물리 시간이다.

## 발견 및 수정

1. **얕은 액체층에서 CPU/GPU 해류가 불연속적으로 달라짐.** 이전에는 유동 가능한 물이 0.2kg을 넘으면 해류를 즉시 켰다. 결빙 경계에서 작은 Float32 차이가 유한한 속도 차이로 커졌다. `weatherClimate.ts`의 해류 가속, 최대 속도, 해류에 의한 물질 이동에 공통 mobility를 적용했다. 0.2–0.5kg 구간은 `x²(3−2x)`로 연속적으로 연결한다. 모세관 토양 수분은 계속 제외하고, 결빙 후 같은 스텝에서 흐름을 다시 제한한다. 이 질량 구간은 게임의 표면 기둥을 위한 수치적·게임적 선택이며 실제 해수 깊이로 해석하지 않는다. 기존 중력에 의한 물 흐름은 계속 별도 계산된다.
2. **약한 실제 흐름을 정지 상태로 표시.** 셀 관측창은 속도를 소수 둘째 자리까지 표시하고, 화살표는 0.0001rad/게임초 미만을 숨겼다. 장시간 해류가 존재해도 `0.00`과 화살표 없음으로 보였다. 작은 값은 소수 넷째 자리 또는 `<0.0001`로 표시하고, 방향 화살표의 표시 기준을 0.000001rad/게임초로 낮췄다. 실제 속도와 방향은 바꾸지 않았다.
3. **화살표의 평탄 단면 좌표 변환 누락.** 기후 색 지도와 단면 색은 같은 셀을 따르지만 기본 LinesMesh 재질은 구면 좌표에 남아 있었다. 화살표도 공통 `sectionShader`를 사용해 평탄화, 절단 띠, 관찰 범위와 기반암 경계를 따른다. 화살표 개수 변경으로 메시를 다시 만들 때도 이 재질을 유지한다. 단면 밖으로 흐르는 성분은 해당 단면에서 짧게 투영될 수 있다.

## 실행 범위

고정 물리 스텝은 1/30게임초이고, 60게임초마다 지역 분포와 수지 표본을 기록했다. 초기 상태는 해안 지형·광물 기반, 실제 물/수증기/CO₂/씨앗 질량을 사용한다. 지형 재료를 유기토양으로 바꾸지 않는다. 별·공전·회전을 매 스텝 갱신했다.

| 실험 | 셀 수 | 게임초 | 물리 스텝 | 조건 |
|---|---:|---:|---:|---|
| 회전 해안 | 42 | 7,200 | 216,000 | 1 AU, 회전 120초, 경사 23.5°, 30공전 |
| 조석 고정 해안 | 42 | 7,200 | 216,000 | 1 AU, 항성 방향에 고정, 30공전 |
| 추운 해안 | 42 | 7,200 | 216,000 | 1.6 AU, 초기 −12°C |
| 건조 광물 행성 | 42 | 2,400 | 72,000 | 물과 생명 씨앗 없음 |
| 대칭 대조군 | 42 | 2,400 | 72,000 | 균일 암석·질소, 햇빛과 회전 없음 |

최장 30공전 검사는 낮은 해상도에서 수행했다. 실제 게임 해상도에서 7,200게임초를 검증했다는 의미는 아니다. 그 해상도는 240게임초 동안 기온·흐름·응결·식생 변화와 저장 재개를 확인했다. 이 구간에서는 새 구름이 생성되지만 강수 문턱에 도달하지 않았다. 실제 강수와 비/눈 전환의 장기 검증은 42셀과 162셀 실험에서 수행했다.

수정 전 전체 7조건도 별도 실행해 비교했다. 수정 후 결과는 `artifacts/climate-soak/final/`, 수정 전 결과는 그 상위 디렉터리에 보존했다. 중간·끝 스냅샷과 원시 JSON은 브라우저와 재개 검사에 사용한 실제 상태다.

## 연결된 변화

아래 값은 수정 후 측정값이다. 기온은 표면 셀 기온이고 속도는 구면의 각속도다.

| 최종 상태 | 기온 범위 °C | 최대 기류 rad/초 | 최대 해류 rad/초 | 누적 비 / 눈 kg | 구름 물+얼음 kg | 식생 kg |
|---|---:|---:|---:|---:|---:|---:|
| 회전 해안 42셀 | −10.01 ~ 7.72 | 0.0005873 | 0.0001324 | 40.40 / 12.87 | 5.078 | 0.449 |
| 조석 고정 42셀 | −55.99 ~ 51.52 | 0.0024307 | 0.0006171 | 41.13 / 21.33 | 4.423 | 1.460 |
| 회전 해안 162셀 | −4.44 ~ 8.44 | 0.0004356 | 0.0000962 | 87.83 / 2.00 | 24.999 | 3.737 |
| 회전 해안 2,562셀 | 18.29 ~ 23.87 | 0.0003808 | 0.0001459 | 0 / 0 | 297.432 | 81.249 |

회전 해안의 식생은 0에서 자라 840게임초에 약 1.524kg을 기록하고, 기온 하강과 결빙에 따라 줄었다. 162셀 실험도 약 780게임초의 5.857kg에서 3.737kg으로 줄었다. 조석 고정 조건은 큰 명암 기온 차이를 유지하며 회전 조건보다 강한 흐름과 다른 식생 분포를 만들었다. 추운 행성에서는 결빙에 따라 해류가 사라지고 식생은 사실상 소멸했다. 건조 대조군에는 물·구름·강수·식생이 생기지 않았다. 대칭 대조군은 모든 셀 기온이 같고 기류·해류가 0이었다.

시계열의 동시 변화만으로 인과관계를 단정하지 않았다. 일반 회귀 검사에서도 다음 연결을 별도로 확인했다.

- 일사·반사율·구름 차광 → 흡수 열, T⁴ 방출·온실 광학 깊이 → 기온.
- 기압·열적 차이 → 접선 기류, 코리올리 → 방향; 균일 조건 → 흐름 없음.
- 기류 → 기체·구름·열 이동과 수렴 냉각 → 응결; 구름의 물/얼음 → 실제 강수.
- 표면 수위·온도·염분·기류 → 해류 → 물·염분·열 이동; 토양 모세관수 제외, 결빙 후 해류 제거.
- 씨앗·광물 뿌리 기반·수분·빛·온도 → 식생 정착/성장/고사; 구름 차광, 물 상태와 CO₂·토양 재순환이 다시 환경에 반영됨.

이 모델은 표면 기둥과 진단적 구름층을 사용하는 게임 모델이다. 심해 열염 순환, 수직 대기 운동량 방정식, 현실의 생지화학 및 지구 기후 예측 정확도를 검증한 것은 아니다. 수식과 단순화의 근거는 기존 `CLIMATE_ECOLOGY_DESIGN.md`에 정리돼 있다.

## 쏠림·수지·폭주

농도는 각 저장고의 최대 셀 질량 비율과 유효 셀 수 `(Σm)²/Σm²`를 함께 측정했다. 회전 42셀 실험의 최종 기체 최대 셀 점유율은 2.438%, 구름은 4.088%이고, 유효 기체 셀 수는 41.995, 구름 셀 수는 34.249였다. 물의 최대 셀 점유율은 초기 13.920%에서 9.258%로 줄었다. 조석 고정의 기체·구름 최대 점유율도 각각 2.613%·4.160%였다. 하나의 셀로 붕괴하는 현상은 없었다.

회전 42셀 식생의 최종 최대 점유율은 28.07%다. 식생의 총량 감소 및 낮은 해상도에서 서식 가능한 셀 감소와 함께 해석해야 한다. 162셀에서는 3.94%, 유효 식생 셀 수 52.20이었다. 식생 분포를 균일하게 만드는 보정은 넣지 않았다.

수지 잔차는 실제 상태와 누적 외부 열·탈출 질량을 비교한다. 보존을 정확한 0으로 주장하지 않는다. 회전/조석 고정 7,200게임초의 전체 표본 중 최대 질량 상대 잔차는 약 0.00171%, 조석 고정의 최대 열 상대 잔차는 약 0.01930%였다. 열 상대 오차의 분모는 초기/최종 총 엔탈피와 누적 순 외부 열의 절댓값 중 최댓값이다. Float32 누적 계산의 잔차를 기록했고 수지 값을 임의로 재설정하지 않았다. 장기 자동 검사의 허용치는 질량 0.05%, 열 0.1%다. 표본마다 저장고가 비음수·유한 값인지 확인하고, 기류 0.12·해류 0.035rad/초 상한과 기온 한계를 검사했다.

## 저장·CPU/GPU·단면

각 수정 후 장기 실험의 끝 상태를 JSON 직렬화, 유효성 검사, 버전 업그레이드, 복원하고 공전·회전을 포함해 30게임초(900스텝)를 더 계산했다. 저장을 거친 CPU와 저장을 거치지 않은 CPU의 셀 배열 및 기후 배열은 정확히 일치했다.

실제 WebGPU 검사는 162셀의 2,400게임초 끝 상태에서 시작했다. 900스텝 동안 CPU와 GPU를 비교하고, 450스텝에서 IndexedDB에 저장·로드한 후 GPU→CPU와 CPU→GPU 전환도 비교했다. 저장 레코드의 모든 필드는 정확히 왕복했다. 기후 계산은 현재 양쪽에서 공유하는 호스트 계산이며, 물질 커널은 각각 CPU와 WGSL을 실행했다.

| 비교 | 측정 최대 차이 |
|---|---:|
| CPU/GPU 기온 | 0.004162°C |
| 물질: 차이 / max(1kg, CPU 셀 질량) | 0.00047692 |
| 기류 벡터 성분 | 0.000000806rad/게임초 |
| 해류 벡터 성분 | 0.000000145rad/게임초 |
| 저장 및 CPU/GPU 전환 후 기온 | 0.004162°C |

수정 전 저장 상태를 똑같이 재개한 비교에서 해류 성분 차이는 0.000073264에서 0.000000148rad/게임초로 감소했다. 이는 게임 해류의 불연속 문턱 수정 효과를 분리해서 확인한 결과다. CPU/GPU는 비트 단위 일치를 요구하지 않고 기온 0.01°C, 물질 위 척도 0.001, 기류·해류 성분 0.00001rad/게임초 이내인지 검사했다.

실제 WebGPU·WebGL 브라우저 각각에서 물질/기온/기압/기류/해류/습도/기단/구름량/수분/씨앗의 10모드를 구면과 단면으로 전환했다. 1,200게임초와 2,400게임초 상태의 **80개 조합 모두 통과했다.** 단면 삼각형의 소유 셀을 역조회해 모든 `climateColor` 속성이 그 셀의 실제 진단 색과 정확히 일치하는지 검사했다. 화살표의 실제 컴파일된 셰이더에도 평탄화와 절단 처리가 들어갔는지 확인했다. 같은 캔버스·같은 상태를 유지했고 렌더 준비 상태와 유한 색 값도 확인했다. 끝 상태의 흐름 화살표는 기류 162개, 해류 100개였으며 단면에서는 관찰 띠와 범위 밖 부분을 절단한다. 앱의 브라우저 오류/경고는 없었다.

단면 상태에서 직접 30게임초 진행한 화면도 확인했다. 1,200→1,230게임초에 기온 범위는 4.9~17.2→4.5~17.7°C, 구름은 24.86→24.94kg, 식생은 5.36→5.43kg으로 변했다. 이 과정은 감사용 페이지의 실제 CPU 상태를 계산하고 같은 관측 지도와 단면을 갱신한다.

## 재현

일반 `npm test`에는 240게임초의 기후·생태 통합 회귀, 얕은 액체의 해류 경계, 약한 흐름 표시, 화살표 메시 재생성 시 단면 재질 유지 검사가 포함된다. 장기 검사는 일반 테스트 시간에 부담을 주지 않도록 명시적으로 실행한다.

```sh
SANDSPHERE_LONG_AUDIT=1 SANDSPHERE_SOAK_OUTPUT=artifacts/climate-soak/final \
  npx vitest run tests/climate-soak.test.ts tests/climate-resolution-soak.test.ts --maxWorkers=2
python scripts/audit-climate-plot.py  # matplotlib가 설치된 Python 환경
npx vite build --config tests/climate-soak.vite.ts
```

브라우저 감사 전용 페이지 `tests/climate-soak-lab.html`은 중간/끝 스냅샷을 읽고 `verifyLayers()`와 `verifyGpu()`를 제공한다. 개발 서버에서 `?cpu=1`은 WebGL을 사용한다. 감사 전용 빌드로 실행할 경우 `artifacts/climate-soak/final/coast-2-{mid,end}.snapshot.json`을 빌드 출력의 `artifacts/climate-soak/final/`에 복사해 제공한다. 정상 앱의 사용자 저장 데이터나 운영 계정에는 접근하지 않았다.

실행 로그, 원시 기록, CPU/GPU의 수정 전·후·최종 비교와 관측 지도 검사 JSON, PNG/PDF 그래프는 `artifacts/climate-soak/`에 보존했다. 이 디렉터리는 로컬 감사 산출물이며 일반 테스트가 이 기록에 의존하지 않는다.

최종 검증: 일반 회귀 238개 통과, 빌드·타입 검사 통과. 일반 실행에서 제외된 14개 중 8개는 명시적으로 실행하는 장기 검사이고, 6개는 이번 기후 감사 범위 밖의 Firebase 에뮬레이터/운영 계정 검사다. 수정 후 장기 7조건과 각 조건의 저장 재개는 별도 실행에서 모두 통과했다. 빌드의 기존 번들 크기 경고는 남아 있다.
