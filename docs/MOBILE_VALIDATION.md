# 모바일 대응 검증 — 2026-10-11

정본: `/Users/garden/Workspace/Projects/sandsphere`. 시작 커밋 `4d3782e`, 브랜치 `codex/localization-alpha6`, 시작 시 미커밋 변경 없음. 기존 `wt/sandsphere-glass-ui`는 수정하지 않았습니다. 모바일 구현 검증은 `0.5.0-alpha.7`에서 수행했으며, 사용자의 후속 배포 요청으로 `0.5.0` 정식 릴리즈를 준비합니다. 변경 내용은 `CHANGELOG.md`의 `0.5.0` 항목에 있습니다.

## 변경

- 세로 화면에서는 시점·재생·시간 표시를 별도 행으로, 넓은 모바일 화면에서는 시점·재생을 나란히 배치합니다. 양쪽 패널 버튼은 시간 표시 행의 여백에 놓입니다. 좁은 시점 줄은 내부 가로 스크롤로 모든 조작을 유지합니다.
- 실제 조작부 높이를 `ResizeObserver`로 측정해 도구·관측·설정·인벤토리·단면 선택과 지도 표시 영역에 반영합니다. `viewport-fit=cover`와 safe area 여백을 사용합니다.
- 주요 버튼·선택·슬라이더를 최소 44px 터치 영역으로 조정합니다. 입력 글자는 16px로 표시하며 브라우저 확대는 막지 않습니다. 지도 메뉴는 작은 화면 안에서 스크롤되고 대시보드 분류 이름이 보입니다.
- Babylon의 터치 카메라 입력을 제외하고 앱의 한 경로에서 그랩·회전·핀치·단면 이동을 처리합니다. 첫 편집은 120ms 유예하지만 짧은 탭은 놓을 때 반영합니다. 두 손가락 이동 이후에는 모든 손가락을 놓아야 편집을 다시 시작합니다. 취소·포인터 캡처 상실·창 포커스 상실 시 입력 상태를 정리합니다.
- 물리·저장 형식·계정 규칙은 변경하지 않았습니다. 기존 200만 픽셀 렌더 버퍼 상한, 최대 1.6배 픽셀 비율, 지형 업로드 15Hz 제한을 유지합니다.

## 검증 환경과 재현

Mac의 별도 헤드리스 Google Chrome, 모바일 뷰포트, `isMobile`, `hasTouch`, DPR 3, CDP `Input.dispatchTouchEvent`를 사용했습니다. WebGL/CPU 대체 경로 `?test=1&cpu=1`에서 별도 테스트 슬롯으로 실행했고 개인 브라우저 프로필을 사용하지 않았습니다.

```sh
npm run dev -- --port 5173 --strictPort
node scripts/browser-mobile.mjs
npm run check:version
npm test
npm run build
```

브라우저 스크립트는 이 Mac에 이미 있는 `artifacts/science/runtime/browser/node_modules/playwright-core/index.mjs`를 사용합니다. 다른 환경에서는 `PLAYWRIGHT_MODULE`과 `CHROME_PATH`로 기존 런타임을 지정할 수 있습니다. 실행 URL과 결과 위치는 `MOBILE_URL`, `MOBILE_ARTIFACTS`로 지정합니다. 새 의존성을 추가하지 않았습니다.

## 실제 확인한 항목

한국어·영어 각각 320×568, 390×844, 430×932, 667×375, 844×390, 768×1024에서 문서의 가로·세로 넘침, 주요 터치 영역, 버튼 중심의 가림 여부, 도구·관측 열기/닫기를 검사했습니다. 각 캔버스가 200만 픽셀 이내인지도 확인했습니다. 좁은 시점 줄은 스크롤 후 홈·구면 조작을 수행했습니다.

게스트 첫 진입 → 캠페인 선택 → 행성 생성, 320px 이름 편집·지도 선택·범례, 도구·관측·인벤토리·행성 조정, 대시보드 모든 분류와 내부 스크롤, 새로고침 후 테스트 저장 이어가기를 확인했습니다. DPR 3에서 UI 글자는 DOM 해상도를 유지합니다.

터치로 한 손가락 그랩 회전이 한 번만 적용되는지, 핀 지정·삭제, 정지 중 탭·드래그 붓기, 재생 중 짧은 탭, 두 손가락 회전·핀치와 편집 억제, 손가락 수 변화·취소·창 포커스 상실 후 다음 입력, 단면 선택·열기·이동을 확인했습니다. 데스크톱 크기 1440×900에서도 마우스 좌/우 드래그와 재료 클릭을 확인했습니다.

safe area는 상단 47px·하단 34px·좌우 24px을 CSS 변수로 주입한 시나리오로 배치와 패널 스크롤을 검사했습니다. 실제 노치 기기 검증은 아닙니다.

## 배포 준비의 추가 확인

기존 30개 검사에는 360px가 없으므로 별도 smoke test에서 360×780과 780×360을 확인했습니다. 각 크기에서 도구·관측 패널을 3회씩 열고 닫았으며, `navigator.gpu`를 제공하지 않는 환경에서 `?test=1` (강제 `cpu=1` 없음)로 실제 미지원 감지 → WebGL `Engine`·CPU 계산·행성 생성·재료 탭까지 확인했습니다. 상세 결과는 `artifacts/mobile/deploy-qa/fallback-results.json`에 있습니다.

30개 검사의 대시보드 스크롤은 DOM `scrollTop`으로, 패널 스크롤은 요소를 화면 안으로 이동시켜 확인했습니다. 실제 손가락 스크롤을 모든 패널에서 자동 검증했다고 해석하면 안 됩니다. 실제 노치·화면 키보드는 미확인입니다.

WebGPU 초기 미지원은 별도 모달 안내 없이 대체 경로로 이어집니다. 실행 중 GPU 계산이 실패하면 CPU로 전환하면서 화면 메시지를 표시하며, 렌더러 초기화가 모두 실패하면 부팅 오류 문구를 표시합니다. 실행 중 장치 상실과 WebGPU 초기화 예외는 코드 확인이며 이번 모바일 브라우저에서 강제로 유발하지 않았습니다.
