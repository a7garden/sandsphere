# 기후 연결 감사와 관측 UI 완성 (2026-10-10)

구름은 고정된 장식이 아니라 셀의 수증기·온도·기류·지형 조건으로 생성된다. 응결물은 계산된 기류를 따라 수송되고, 강수하거나 불포화 조건에서 다시 증발한다. 이번 작업은 [기후·식생 설계](CLIMATE_ECOLOGY_DESIGN.md)의 연결을 검수하고 관측값과 표시를 실제 계산에 맞췄다. 지구 날씨를 예측하는 수직 대기 모형의 완성을 뜻하지 않는다.

## 연결 검수

| 경로 | 연결과 게임용 범위 |
|---|---|
| 궤도·자전 → 햇빛 | 거리의 역제곱 에너지, 공전·자전·축 기울기가 셀의 일사에 반영된다. 활성/배경 행성 모두 같은 소단계를 사용한다. |
| 일사·재료·기체 → 열 | 재료 반사율, 구름 차폐, CO₂·수증기·메탄의 회색체 온실 근사와 T⁴ 방출이 공유 엔탈피를 바꾼다. |
| 열·압력·염분 → 상 변화 | 얼음/물/수증기 및 구름 물/얼음의 잠열, 염수의 활동도, 압력별 비등 조건을 계산한다. 고온·저압 상 모델의 기존 제한은 UI에 표시한다. |
| 기압·온도·회전 → 기류 | 기체 컬럼 무게와 열 두께 차이, 코리올리 편향, 마찰을 접선 흐름으로 근사한다. |
| 바람·수두·온도·염분 → 해류 | 액체 표층의 바람 응력과 높이/밀도 차이를 사용한다. 유기물에 붙잡힌 물·용존염은 표층 해류로 전량 유출되지 않는다. 얼어서 흐를 액체가 사라지면 같은 단계에서 속도를 지운다. |
| 흐름 → 물질·열 수송 | 기체·수증기·응결물·씨앗 및 액체 물·염분을 질량과 엔탈피로 함께 수송한다. 출발 셀 공급량을 제한한다. |
| 수증기·수렴·지형 상승 → 구름 | 대표 구름층을 `지표 T − 12°C − clamp(60 × lift, −8, 12)`로 진단한다. 구름 물/얼음 비율에 따른 포화량, 과포화 응결과 재증발을 사용한다. 수직 대류를 직접 풀지 않는다. |
| 구름 → 강수 → 표면 | 응결물 축적이 비/눈 낙하와 표면 물/얼음으로 이어진다. 새로 응결한 구름의 강수 계산은 다음 1/30 게임초 단계에서 진행된다. |
| 수분·빛·온도·염분·기반 → 생태 | 씨앗이 있고 적합하면 모래·점토에서도 발아한다. 기존 식생도 같은 뿌리 조건으로 성장·확산하고 악조건에서는 쇠퇴한다. 유기토양은 보수력·성장 개선 자원이다. |
| 생태 → 토양·탄소·기후 | 씨앗/생물량/유기물 전환과 CO₂ 흡수·호흡이 질량·열 장부와 연결된다. 탄소는 1:1 게임 질량 대용이며 광합성 화학양론이 아니다. |
| 상태 → 저장·재개·관찰 | 셀과 기류·해류·씨앗 분포를 저장한다. CPU/GPU 전환과 배경 행성도 같은 기후 계산을 사용한다. 구면·펼친 단면은 같은 상태를 읽으며 표시 전환은 물리를 바꾸지 않는다. |

## 수정한 누락

1. 응결은 상승 보정과 얼음 포화량을 사용했지만 관측 습도·온도는 이를 빠뜨렸다. `cloudConditions`와 `WeatherClimate.conditions`를 응결·습도 지도·기단 분류·지점 관측이 공유한다. 저장된 속도와 현재 지형에서 재계산하므로 재개 직후나 정지 중 편집에도 진단이 낡지 않는다.
2. 씨앗 발아와 기존 식생 성장·확산의 기반 조건이 달랐다. CPU와 WGSL의 식생 서식 조건에 모래·점토·토양의 뿌리 가능량을 함께 적용했다. 기후를 끈 기존 물리 실험은 유지한다.
3. 단계 마지막의 결빙·생물량 변화로 유동 저장량이 사라져도 해류/기류가 남을 수 있었다. 완료 상태에서 저장량을 확인해 정리한다.
4. 일시정지가 날씨 관측을 가렸다. 현재 구름 저장량과 마지막 완료 단계의 응결·비·눈 유량을 나눠 표시한다. 정지 중 0시간 편집은 마지막 유량을 지우지 않는다. 행성을 불러오거나 전환하면 유량은 다음 물리 단계까지 `—`이며, 과거 유량을 만들어내지 않는다.
5. 작은 응결물은 구름 덩어리 렌더의 가시성 임계값 아래에서 관찰하기 어려웠다. 물방울+얼음 질량을 직접 읽는 구름량 지도를 추가했다. 구름 덩어리의 모양은 시각 근사이며 지도는 셀별 수치를 표시한다.
6. 속도 범례와 관측 단위가 달랐다. 색은 속도, 화살표는 방향으로 설명하고 평균 셀 간격/게임초 단위를 통일했다. 실제 m/s로 환산하지 않는다.
7. 씨앗은 총 질량에 포함됐지만 생물 총량과 CSV 지표에서 빠졌다. 휴면 씨앗 지표와 생물 총량에 포함했다. 기존 CSV와 저장된 관측 기록은 계속 읽고, 당시 측정되지 않은 씨앗 값은 미상으로 남긴다. 과거 생물 총량을 다시 계산해 덮어쓰지 않는다.

## 관측 UI

- 지표 온도 바로 아래에 지점 기압, 진단 구름층 온도·습도, 구름 질량, 기류·표층 해류의 6개 수치를 배치했다.
- 행성 날씨 패널은 저장량과 게임초당 유량, 정지/편집/미측정 시점을 구분하고 구름량·습도 지도 바로가기를 제공한다.
- 물질을 포함한 10개 지도 모드를 구면과 펼친 단면에서 사용할 수 있다. 구름 표시를 숨겨도 물리는 계속 계산한다. 새 표시 설정은 구름을 켜며 기존 명시적 숨김 설정은 존중한다.
- 씨앗 질량과 분산 흔적, 뿌리 기반의 부족을 관측 정보에 표시한다. 작은 화면은 기존 관측 패널 펼치기 동작을 사용한다.

## 회귀 검증

전체 Vitest는 35개 파일, **229개 테스트 통과**이며 타입 검사·제품 빌드도 통과했다. 결과를 아래 로그에 보존한다. Firebase 에뮬레이터가 필요한 별도 계정 테스트 3건은 실행 조건이 없어 건너뛰었다. 기존 큰 번들 경고는 남는다.

- `tests/climate-coupling.test.ts`: 수렴 냉각과 저장 재개 진단 일치, 얼음 포화량, 180단계 수증기→구름→강수와 질량/열 장부, 건조 행성의 물 생성 금지, 구름 차폐·온실 피드백, 뿌리 조건, 작은 구름량 지도, 결빙 직후 해류, 정지 관측 유지.
- 기존 기후 테스트: 코리올리, 기압차 바람, 보존 수송, 무생명 행성, 모래 정착과 악조건 쇠퇴, 씨앗 질량, 토양 보수력, 활성/배경/재개 동등성.
- 실제 WebGPU/CPU: 162셀, 180단계. 최대 온도 차이 **0.00075150°C**, CPU↔GPU 재개 차이 **0.00042725°C**, 물질 차이 **1.6093×10⁻⁶** (`max(1, kg)` 분모), 기류 성분 차이 **8.4285×10⁻⁸ rad/게임초**. 기반암만 있는 부적합 식생도 포함했다.
- 질량 장부 잔차: CPU **−0.00005694kg**, GPU **−0.00004269kg**. 엔탈피 잔차/초기 엔탈피: CPU **4.9188×10⁻⁸**, GPU **6.2709×10⁻⁶**. 모든 값 유한·질량 비음수, IndexedDB 셀/기후 왕복 정확 일치. CPU/GPU 모두 같은 호스트 기후 후처리를 사용하므로 GPU 기후 커널 전체의 독립 비교라고 해석하지 않는다.
- 지도: **10모드 × 구면/단면 × WebGPU/WebGL = 40조합**. 셰이더 준비, 유한 색, 단면 색, 같은 캔버스, 정지 셀 상태 불변을 확인했다. 세 검증 페이지의 오류 로그는 비어 있었다.
- 제품 UI: 격리한 검증 행성에서 모래·씨앗을 선택하고 물을 공급했다. 유기토양·식생 공급 없이 **식생 1.4kg**, **구름 0.59kg**, **응결 0.0782kg/게임초**를 관측했다. 정지 후 지도 바로가기를 전환해도 관측 유량이 유지됐다.
- 반응형/테마: 320·375·414·768px에서 지점 수치 넘침 없이 접근 가능하며 밝은/어두운 UI를 시각 검수했다. 모바일 관측 펼치기와 단면 지도 전환을 실제 조작했다.

## 남는 과학적 단순화

단일 공유 열 저장층과 진단 구름층, 감쇠 접선 흐름, 표층 해류, 단순 생태 자원망으로 제한한다. 수직 대기 방정식, 심해 열염 순환, 흐름 운동 에너지의 열 환원, 산소 생성과 N/P 영양 화학, 종별 식생 생리는 계산하지 않는다. 이 항목을 연결 누락이 없는 것으로 표현하지 않으며, 현재 게임 모형의 명시적 제외 범위로 유지한다.
