# 0.7.0 성능 최적화 검증

2026-10-23. 사용자가 전체 성능 연구 후 구현과 운영 배포를 요청했다. 물리·Worker·저장·화면·시작 경로를 최적화하고 배포 후보를 검증했다. 제품 코드의 기준 커밋은 `fcf5d49328b04156958b1eff4f9864c969321daf`이며, 이후 릴리즈 준비 변경은 문서와 검증 자료다.

통합 CI는 **782개 통과, 조건부 70개 제외**, Firebase 규칙은 **5개 통과**했다. 버전·TypeScript·일반 빌드와 별도 운영 빌드도 통과했다. 실제 운영 전달 여부는 아래 배포 기록과 도메인의 `release.json`으로 구별한다.

## 비교 기준과 보존 범위

기준은 [최초 연구](PERFORMANCE_RESEARCH_2026-10-23_KO.md)의 `0.7.0-alpha.18` 미커밋 통합 상태다. 당시 Git HEAD는 `02d53d7`이었지만, 그 커밋 자체인 0.6.1을 성능 기준으로 쓰지 않았다. 기존 개발 변경을 보존해 0.7.0에 함께 통합했다.

초기 백업에는 먼저 바뀐 spectral 파일과 새 테스트가 포함되어 있었다. 검증된 수정 전 사본으로 보완한 별도 아카이브의 기존 517개 소스 해시가 최초 연구의 해시와 일치한다. 원본·보완본을 모두 보존했다. 근거는 `performance/2026-10-23/optimization-baseline.json`, `optimization-reference.json`이다.

격자·시간 간격·공통 물리 과정·Float64 재고와 열 잔여·보존 허용치를 축소하지 않았다. CPU 전후 비교 7조건과 브라우저 JS/Worker/WASM 비교는 지표뿐 아니라 기후 체크포인트, lift, 에너지·유출입 결과까지 정확히 일치했다. 이는 시험 범위의 동등성이며, 실재 행성 기후 재현을 뜻하지 않는다.

WASM은 초기 자체 검사를 통과할 때 사용한다. 지원하지 않는 환경, 초기화 실패·시간 초과·실행 trap에서는 JavaScript로 복귀한다. 계산 백엔드는 계속 CPU이며 렌더링 WebGPU와 구별한다. GPU에 대기를 상주시켜 계산하는 방식은 정확성·효익이 검증되지 않아 채택하지 않았다.

## 저장 용량·응답·복구

기존 전송 표현 64MiB, gzip 20MiB 한도를 유지한다. Float32로 정확히 왕복하는 값만 4바이트에 담고 나머지는 Float64로 보존한다. 디코더는 확장 숫자 벡터 합계 128MiB를 할당 전에 검사한다. 정본 스냅샷은 바꾸지 않으며 기존 JSON도 읽는다.

2,562셀에서 14단계 진행한 8행성·두 모드·관측 16,384점을 포함한 CI 시험:

| 조건 | 전송 표현 | gzip | 결과 |
| --- | ---: | ---: | --- |
| 거대 행성 8개 | 40,187,035B | 12,691,000B | 한도 내, 정확 복원·다음 단계 일치 |
| 젖은 행성 8개 | 44,604,331B | 15,033,112B | 한도 내, 정확 복원·다음 단계 일치 |

CPU 계측 JSON의 `saves`는 비교용 옛 JSON 표현의 비용이다. 그 숫자를 새 바이너리의 용량이나 전체 저장 비용으로 해석하지 않는다.

실제 브라우저에서 진행된 1/4/8행성 각각 두 번, typed capture→준비 Worker→IndexedDB 경로는 **6/6 통과**했다. 전체 시스템·압축 바이트 SHA256·다음 단계 지표와 기후가 같다. 각 조건 2회 관측이며 통계적인 p95 추정은 아니다.

| 전체 행성 | 캡처 | Worker 전송 호출 | IndexedDB put 호출 | 관측 |
| ---: | ---: | ---: | ---: | --- |
| 1 | 0.6–0.7ms | 0.2ms | 0.5–0.8ms | long task 없음 |
| 4 | 5.0–5.3ms | 0.2ms | 1.4–1.5ms | long task 없음 |
| 8, 첫 다른 모드 전송 | 5.3ms | 78.7ms | 4.1ms | long task 1개 |
| 8, 캐시 재사용 | 5.6ms | 0.2ms | 3.0ms | long task 없음 |

표는 동기 메인 스레드 비용이다. Worker 준비와 실제 저장 완료까지의 전체 지연은 더 길고 원시 결과에 따로 있다. 첫 다른 모드 전송의 구조화 복사 비용은 남아 있다. 별도 검증 슬롯을 사용했으며 실계정의 클라우드를 임의로 변경하지 않았다.

브라우저 저장 회귀 **13/13**, 실제 pagehide 후 복원도 통과했다. 50,638,914바이트 저장은 localStorage가 가득 찬 상태에서도 복구됐고 페이지 이동 후 SHA256이 같았다. 원문 최초 1회 백업, 잘못된 종료 자료의 fallback, 중단 원자성, 세대별 늦은 준비·쓰기 차단을 포함한다.

## 로딩과 실제 게임

앱 entry의 정적 의존 그래프는 raw 5,229,657→4,659,023B, gzip 2,212,032→2,044,108B로 줄었다. 하지만 새 준비 Worker는 별도 raw 2,393,098B / gzip 1,441,781B이며, solver Worker는 raw 2,369,831B / gzip 1,432,862B다. 전체 Worker를 합친 다운로드가 같은 비율로 줄었다고 주장하지 않는다.

기본 렌더러에서 발견된 지연 컴파일러 준비 문제를 수정했다. 지원 확인·장치·컴파일러 준비 전체에 3초 제한을 두고 실패 시 새 canvas로 WebGL을 시작한다. 실제 최종 검증에서는 기본 WebGPU가 성공했고, 첫 로컬 Vite 시작의 dev inspector 준비는 약 1.27초였다. 200ms polling·로컬 자원을 쓰는 값으로 계정·운영 네트워크 시작 속도는 아니다.

실제 앱 1행성, 1280×720 DPR 1의 각 15초 계측:

| 상태 | 평균 프레임 | p95 | 50ms 초과 | long task |
| --- | ---: | ---: | ---: | ---: |
| 일시정지 | 16.64ms | 17.5ms | 0 | 0 |
| 실행 | 16.73ms | 17.5ms | 0 | 0 |

실제 UI에서 물 붓기·950°C 가열·지점 picking·14셀 단면을 확인했다. 일시정지 중 이름을 바꾼 뒤 새로고침해 이름·정지·시간 0:15:34와 해당 지점의 물 2.67kg·온도 950°C를 다시 확인했다. 열 편집 후 정지 상태라 후속 반응 전의 관측이다. `optimization-results/actual-game-section.png`, `actual-game-restored.png`에 화면을 보존했다.

## 통합 과정과 남은 한계

첫 전체 시험의 두 실패는 수정 후 전체 CI를 재실행했다. 하나는 공개 기후 JSON 속성 순서, 하나는 직접 지표 편집 후 잔여 재고 재조정 우회였다. 순서를 보존하고 실제 지표 변경이 있을 때 기존 조정 경로를 사용하는 방식으로 해결했다. 초기 저장 성능 fixture가 모든 배경 행성을 정지시킨 실패 기록도 남겼으며, 배경이 실제 진행하는 최종 6/6 결과와 구별한다.

릴리즈 대기 중 GitHub Ubuntu 검사도 확인했다. 15분 작업 제한으로 전체 실행이 중단됐고, 두 장기 검사의 개별 시간 제한도 초과했다. 해당 두 테스트의 단계·수치 기준은 그대로 두고 한도를 120초로, GitHub 전체 작업을 45분으로 늘렸다. 또한 JS와 WASM 모두 기존 ARM에서 기록한 네 분광 해시와 달랐으므로, 최적화 전 다섯 소스를 원본 SHA256으로 고정해 같은 런타임에서 매 단계·초기화·전체 체크포인트를 `Object.is`로 직접 비교하도록 보강했다. 원래 ARM 해시는 해당 기록 환경의 추가 검사로 유지한다. Linux를 제외하거나 허용 오차를 넓히지 않았다. 제품 소스와 v0.7.0 태그는 바꾸지 않으며, 이 테스트·CI 전용 후속 변경은 별도 커밋으로 검증한다. 로컬 관련 25개·시간 한도 대상 2개·TypeScript가 통과했고 Ubuntu 최종 결과는 배포 절에 덧붙인다.

**고해상도 물리의 33.33ms/단계 목표는 아직 달성하지 못했다.** 실제 앱 실행의 물리 시간 진행은 약 0.184배였고 화면 표시 시간으로 약 11초/초였다. 60fps에 가까운 화면 갱신을 물리 1배속 달성으로 해석하지 않는다. 모바일 실기기·배터리·장시간 열 안정성은 검증하지 않았다. 조건부 70개는 기본 테스트의 통과 수에 포함하지 않는다.

## 재현 자료

원시 결과와 파일 해시는 `performance/2026-10-23/optimization-results/`에 있다. `verification.json`은 제품 소스 해시·7조건 비교·CI·수동 검증 범위를 담는다. 초기 SIMD 실험은 `wasm-experiment/`, 최종 제품 경로는 `candidate-wasm/cpu.json`과 `browser/browser-physics-wet.json`으로 구별한다.

```sh
node --expose-gc docs/performance/2026-10-23/optimization-cpu-harness.mjs
SANDSPHERE_PERF_SPECTRAL_WASM=1 \
  SANDSPHERE_PERF_OUT=/tmp/sandsphere-performance-wasm \
  node --expose-gc docs/performance/2026-10-23/optimization-cpu-harness.mjs
node docs/performance/2026-10-23/optimization-serve.mjs
```

브라우저 inspector는 같은 디렉터리의 `optimization-browser-lab.html`, `background-lab.html`, `persistence-performance.html`, `optimization-game-lab.html`이다. 명시적으로 1280×720와 DPR 1을 설정한다. 화면 크기만 바꿔서는 DPR이 바뀌지 않는다. 초기 실행 URL은 원시 기록에 보존했고, 두 inspector의 보관 위치만 artifacts에서 docs로 옮겼다. Gitea CI run/job 48에서 제품 커밋 `fcf5d49`가 전체 검사를 통과했다. 정식 `v0.7.0` 릴리즈 workflow는 태그를 다시 검사·빌드한 뒤 압축본과 SHA256을 첨부하고 Firebase 규칙·Cloudflare를 배포한다. 도메인의 `release.json`에서 태그와 전체 커밋이 같아야 완료로 판정한다. 실제 배포 영수증은 완료 후 이 절에 추가한다.

기존 v0.6.1 압축본과 SHA256을 내려받아 검증해 보관했다. 그러나 새 Snapshot 11·바이너리를 옛 0.6.1이 읽는다고 가정하지 않는다. 복구 전 기본 슬롯·종료 체크포인트·`before-binary-v1` 원문을 보존하고, 호환 버전 또는 0.7.0 디코더로 추출·재개 검증한다. 세부 절차는 [운영 문서](OPERATIONS.md)의 ‘0.7.0 저장 표현과 복구’를 따른다.
