# 공통 법칙·장시간 안정성 종합 점검

> 이 문서는 alpha.17 당시의 감사 기록이다. 후속 수정과 현재 회귀 검사는 [alpha.18 검증 기록](STABILIZATION_ALPHA18.md)을 따른다. 아래 재현 검사 파일은 후속 작업에서 정상 동작을 요구하는 회귀 검사로 전환했으며, 당시 실패 증거는 `artifacts/audit-alpha17`에 보존한다.

2026-10-18, 0.7.0-alpha.17 작업 상태. 이번 작업은 점검이며 생산 엔진을 수정하거나 배포하지 않는다.

## 점검 기준과 범위

구형 파우더 토이의 재료·열·조성·지형 실험을 기준으로 본다. 유한 재고의 국소 수송과 반응, 내부·외부 에너지 교환, 추적하는 운동량, 저장 재개와 실행 경로의 일관성을 검사한다. 서로 다른 상의 구성식이나 명시적인 게임 근사는 그 자체로 오류로 분류하지 않는다.

완료 조건은 각 담당 영역의 코드 점검, 의심 경로의 최소 재현, 기존 검증과 새 검증의 구분, 우선순위와 미검증 범위 기록이다. 모든 입력·무한 시간 안정성의 증명을 주장하지 않는다. 검증 허용치를 완화하지 않으며 실패 기록을 보존한다.

| 영역 | 담당 (모두 gpt-6.1-sol / xhigh) | 상태 |
| --- | --- | --- |
| 지표·반응·생태·해류·고체 | audit_surface18 | 점검 완료 |
| 일반/깊은 대기·복사·구름·입자 | audit_atmosphere18 | 점검 완료 |
| 활성/배경·Worker/GPU·도구·저장 | audit_execution18 | 점검 완료 |
| 장시간·극한 조합·검증 공백 | audit_stability18 | 점검 완료 |
| 증거 대조·판정·보고 | 주 에이전트 | 재현·판정 완료 |

생산 소스 해시는 `artifacts/audit-alpha17/source-manifest.json`에 고정했다. alpha.17 기존 661개 검사·브라우저 103건·대용량 저장 검증은 이전 실행 증거이며, 이번에 새로 실행한 검사로 세지 않는다.

## 확정된 문제

아래는 수정 완료 목록이 아니다. 재현한 실패와 다음 수정의 범위다. P1은 저장 지속성 위험, P2는 특정 조건의 계산·관측 계약 위반, P3는 확인된 정확도 개선 사항이다.

### 1. P1 — 실행 재고와 저장 재고의 범위가 다름

`src/sim/storage.ts:58,66`은 셀별 재료를 100,000 이하로만 허용하지만
`src/sim/model.ts:393`의 정상 공급은 그 제한을 적용하지 않는다. 유효한 모래
99,999 kg에 일반 일시정지 붓기 6.6666667 kg를 더하면 실제 재고는
100,005.6666667 kg로 정상 계산된다. 이후 `src/sim/system.ts:38`에서 항성계
저장 전체가 거부된다. 이전 정상 저장은 보존되지만 그 뒤 변경은 저장되지 않는다.
질량 정밀도나 IndexedDB 용량 문제가 아니라 실행·저장 계약 불일치다.

다음 수정은 지원 가능한 유한 재고 범위를 실행·직렬화·검증에 함께 정의해야 한다.
저장할 때 재고를 잘라내서는 안 된다. 증거: `execution-save-ceiling.json`.

### 2. P2 — 극저온 상태의 층상 대기 초기화가 지표 에너지를 과다 인출

`src/sim/layeredAtmosphere.ts:201-204`의 초기 대기 프로필은 −150°C 하한을
사용한다. 유효한 −272°C, 암석 8 kg·질소 0.3 kg 상태에서 대기를 이 온도에
맞추고 비용을 지표에 청구해 지표가 −273.53385684°C가 된다. 다음 단계가
`src/sim/model.ts:358`에서 거부된다. 합계 에너지 잔차는 약 5.8e-11 kJ에
불과해도 열역학적으로 허용된 상태가 아니다. 단계 롤백은 정확히 작동한다.

이는 이미 층화된 대기의 장시간 진화에 −150°C 하한이 다시 생겼다는 뜻이
아니라, 초기화·기후 활성화·옛 저장의 층화 경로 문제다. 초기 프로필도 유한
열·위치에너지로 만들고 불가능한 기하 조건을 명시적으로 처리해야 한다.
증거: `surface18-cold-activation.json`.

### 3. P2 — 증발·얼음 침강에 운반 운동량이 빠짐

`src/sim/layeredAtmosphere.ts:426`은 증발 질량을 추가하면서 기존 공기 속도를
유지한다. 정지한 물이 100 m/s 공기로 들어가는 1물리초 검사에서 수평 운동량이
4.3115e-5 kg·m/s 증가했다. 혼합 후 속도는 99.998585 m/s여야 하지만 100이다.
에너지 잔차는 약 −9.1e-13 kJ로, 에너지 보존만으로 잡히지 않는다.

같은 파일 `:570`의 층간 얼음 침강은 질량·에너지를 옮기지만 받는 층의 수평
운동량을 갱신하지 않는다. 지표에 도달한 강수 없이 1초 만에 1.6659e-10 kg·m/s를
잃었다. 수치는 작은 최소 재현이며 실제 장기 영향의 크기까지 측정한 것은 아니다.
다음 수정은 증발·강수·입자를 동일한 질량/엔탈피/운동량 교환으로 처리하고,
지표 반작용과 혼합 소산을 명시하는 것이다. 증거: `atmosphere18-report.json`.

### 4. P3 — 기체 조성이 바뀌어도 복사 캐시가 유지됨

`src/sim/layeredAtmosphere.ts:499`의 캐시 무효화는 총 질량·온도·구름·먼지·
그을음을 비교하며 기체별 조성을 비교하지 않는다. 같은 질량의 N₂를 CO₂로
바꾼 국소 민감도 검사에서는 오래된 순복사와 새 계산이 6.46377 W/m² 달랐다.
실제 생산 `dynamics(1)`의 이류만으로 CO₂가 들어오는 별도 검사도 캐시 누락을
재현했다. 그 1초 사례의 차이는 0.00061232 W/m²로 더 작으며 과장하지 않는다.
기존 캐시는 다른 조건이 깨지지 않으면 300물리초까지 사용된다.

다음 수정은 광학적으로 중요한 조성 변화에도 캐시를 갱신하는 것이다.
증거: `atmosphere18-report.json`의 두 radiation-cache 사례.

### 5. P2 — 지원한다고 판정한 깊은 대기를 저장할 수 없음

`src/sim/planetDefinition.ts:61-66`이 허용한 사용자 정의 저중력
0.0981 m/s²의 수소·헬륨 행성은 초기화에 성공하지만, 계산된 상층 높이
76,526,490.7 m가 `src/sim/deepAtmosphere.ts:32`의 저장 한도 3,000,000 m를
넘어 `validClimate`가 실패한다. 단순히 저장 한도만 늘리면 구면·정역학 모델의
적용 범위를 넘길 수 있다. 행성 지원 판정, 기하 모델과 저장 범위를 함께 맞춰야 한다.
기본 목성·토성 프리셋의 실패는 아니다. 증거: `atmosphere18-report.json`.

### 6. P2 — 활성 행성의 캠페인 판정이 과거 대기 재고를 읽음

`src/main.ts:1021`은 행성 기록에 새 state를 넣지만 이전 climate를 유지한다.
`src/sim/progress.ts:36`이 그 climate의 정본 재고를 읽으므로, 가열 30단계 뒤
수증기 1.344819832 kg·구름/얼음 0.101472466 kg로 물 과제 조건을 달성했어도
화면의 판정 재고는 0/0이고 완료되지 않는다. 같은 시점의 일관된 스냅샷은
완료된다. 관측 시점의 state와 climate를 함께 게시해야 한다.
증거: `execution-campaign-stale-climate.json`.

## 오류와 구분한 정책·근사

- `src/main.ts:1009,1018`은 카메라 드래그 중 모든 행성의 계산을 멈추고 대기 시간을 버린다. “시점 이동 중”으로 표시하는 의도적인 성능 정책이지만 카메라 독립 원칙과는 다르다. 같은 시뮬레이션 시각에서 방정식이 달라졌다는 증거는 아니다.
- 고체의 과감쇠 이동, 생체량의 독립 중력 위치에너지·이동 동력 미추적, 낙하 도구 입자의 시각적 반동은 완전한 입자 역학이 아니다. 현재 추적 장부의 손실과 별도로 확장 범위를 명시해야 한다.
- 깊은 대기의 −250..2500°C/5000 m/s 적용 한도 자체는 숨은 온도 보정이 아니다. 허용 상태에서 이 범위를 벗어나는 모든 경로를 이번 검사로 확인한 것은 아니다.
- 고온 earth-spectral 계산은 Planck 표 밖에서 선형 외삽한다(`src/sim/spectralRadiation.ts:37-40`). 아래 고온 검사의 안정성은 실제 고온 복사·플라스마·항성 물리의 정확도를 뜻하지 않는다.
- 기존 일반 대기의 응결물 하중을 기압 표시에 모두 포함하는지도 추가 정리가 필요하다. 관측 계산의 코드상 차이는 확인했지만 독립 수치 재현을 확정 문제에 포함하지 않았다.
- 기존 `tests/helpers/stabilityScenario.ts:38` 및 `tests/helpers/airInventory.ts:6`은 지표의 `surfaceMassCarry`를 합산하지 않는다. 따라서 이전 일부 수지 검사는 현재 정밀 재고의 완전한 측정이 아니다. 이번 새 장시간 검사는 `totals(state, climate)`로 정본 재고를 계산했다. 기존 도우미도 다음 수정에 포함해야 한다.

## 새로 실행한 안정성 검사와 재현 증거

`tests/audit-stability18.test.ts` 최종 12개 조건은 통과했다. 근거는
`artifacts/audit-alpha17/stability-final.log`와
`artifacts/audit-alpha17/stability/2026-10-18T13-36-39-074Z/`다.

| 범위 | 새 검사 결과 |
| --- | --- |
| 습윤 목성·토성 대기 | 각각 3,000단계 + 재개 비교 5단계, JSON 교체 재개 5회 통과. 최종 질량 상대 잔차 7.05e-16 / 1.22e-15, 에너지 장부 상대 잔차 1.53e-14 / 4.92e-15 |
| 혼합 재료와 외부 조건 편집 | 간소화/층상 각각 3,000단계 + 재개 비교 5단계 통과. 최종 원소 정규화 잔차 2.46e-10 / 2.11e-9, 에너지 장부 상대 잔차 3.67e-10 / 8.81e-10 |
| 깊은 대기 시간·격자 | 실제 적분 간격 축소와 12/42/162셀의 부드러운 온도 모드 검사 통과. 완전한 공간 수렴이나 기후 재현 증거는 아님 |
| 매우 뜨거운 얇은 일반 대기 | 4000/10000°C × 구름/그을음/CO₂, 각 60단계에서 유한성·비음수·수지 검사 통과. earth-spectral 모델에 한정 |

별도 지표 혼합 재료 20조건은 19조건이 60단계 후 유효했고, 한 조건은 위 극저온
초기화 실패였다. 최초 탐색에서 ambient 제어값을 지원 범위 밖으로 설정해 나온
저장 실패는 검사 입력 오류로 제외했고 수정한 입력으로 다시 실행했다.

실패 재현은 정상 작동 검사와 분리한다. 주 에이전트가 실행/저장 사례 2개와
대기 사례 5개를 독립 재실행했다. 대기 검사는 `it.fails`로 의도한 계약의 실패를
보존하므로 Vitest의 “expected fail”은 물리 통과가 아니다. 지표 초기화 재현도
독립 재실행했으며 로그는 `independent-reproduction.log`,
`independent-atmosphere-final.log`, `independent-surface.log`다.

검사는 기본 회귀와 분리된 선택 실행이다:

```sh
AUDIT_ALPHA17=1 npx vitest run tests/audit-execution18.test.ts tests/audit-stability18.test.ts --maxWorkers=1 --testTimeout=60000
AUDIT_ATMOSPHERE18=1 npx vitest run tests/audit-atmosphere18.test.ts --maxWorkers=1
AUDIT_SURFACE18=1 npx vitest run tests/audit-surface18.test.ts --maxWorkers=1 --testTimeout=60000
```

## 다음 작업 순서

저장 범위 일치 → 극저온 초기화의 유한 에너지 처리 → 증발·강수 운동량 →
조성 변화의 복사 갱신 → 일관된 관측 스냅샷 → 카메라와 계산 시계 분리를 권한다.
새로운 전역 온도 보정이나 재고 보정 대신 기존 재고·교환 계약을 완성하는 작업이다.
확인된 문제를 수정하기 전에는 “모든 공통 법칙과 장시간 안정화 완료”로 판정하지 않는다.

최종 확인에서 생산 소스 132개의 해시가 점검 시작과 모두 같았다
(`source-verification.json`). TypeScript와 `git diff --check`도 통과했다.
이번 변경은 이 보고서와 선택 실행용 재현 검사 4개 및 증거 파일이며,
엔진 수정·버전 변경·새 브라우저/GPU 인증·배포는 수행하지 않았다.
