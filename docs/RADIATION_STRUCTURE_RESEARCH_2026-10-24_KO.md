# 복사 무효화 구조 연구

2026-10-24. 0.7.0 성능 연구가 복사 계산을 스텝 시간의 지배 항으로 확인한 뒤,
무효화·캐시 구조를 어떻게 바꿀지 연구한다. 이 문서는 코드 변경이 아니라
구조 제안이며, 수치는 명시한 경우를 제외하고 기존 계측 결과에서 읽은 값이다.
설계 기준은 [공통 법칙과 창발적 시뮬레이션](SIMULATION_PRINCIPLES.md)이고,
선행 연구는 [0.7.0 성능 연구](PERFORMANCE_RESEARCH_2026-10-23_KO.md)와
[검증 기록](PERFORMANCE_OPTIMIZATION_RELEASE.md)이다.

## 측정된 병목 구조

0.7.0 하니스가 기록한 복사 캐시 카운터(`optimization-results/candidate-wasm/cpu.json`,
6단계 준비 후 3단계, 2,562셀, 물리 시간 기준)는 원인을 이미 특정하고 있다.

| 시나리오 | 열 호출 | 재구축 | 재구축율 | 트리거 |
| --- | ---: | ---: | ---: | --- |
| 마른 질소 162 | 972 | 0 | 0% | — |
| 마른 질소 642 | 3,852 | 0 | 0% | — |
| 마른 질소 2,562 | 15,372 | 0 | 0% | — |
| 젖은 해안 2,562 | 15,372 | 11,495 | 74.8% | **전부 수증기 1% 규칙** |

- 재구축 11,495건의 트리거가 `gas[0]`, 즉 `AIR_GAS_INDICES`의 수증기 하나뿐이다.
  온도·질량·구름·먼지·그을음·표면 온도·알베도·나이 항은 0이다.
- 선행 연구의 별도 계측(같은 해상도, Node)에서 복사 구간은 마른 22.82ms 대
  젖은 658.05ms였다. 재구축 1건당 한계 비용은 약 55µs, 캐시 적용만일 때는
  약 6µs다. 즉 젖은 복사 비용의 대부분이 "수증기 재고가 1% 움직였다"는
  이유의 전체 분광 재계산이다.
- 마른·메탄 시나리오는 같은 창에서 재구축이 0이다. 같은 코드가 시나리오에 따라
  29배 차이를 내는 지점이 무효화 규칙이다.

## 현재 구조

`layeredAtmosphere.ts`의 열 단위 복사 캐시(`radiation()`, :646–662)는 이렇게 동작한다.

1. **캐시 내용.** 열마다 나이, 순 longwave, 표면·대기 단파 계수, TOA 순,
   반사율과 함께 재구축 시점의 표면 온도·알베도·모드, 층마다 온도·층 질량·구름
   값을 저장한다(`RAD_STRIDE=8+5×AIR_LAYERS`, `AIR_LAYERS=11`).
   별도 `gasRadiationCache`에 층·가스별 재고를 저장한다.
2. **무효화 조건(하나라도 참이면 재구축).** 캐시 부재, 나이 ≥ 300 물리 초,
   표면 온도 1K, 알베도 0.01, 모드 변경, 층 온도 1K, 층 질량 2%,
   구름 물+얼음 0.01, 먼지·그을음 `max(1e-15, 1%)`,
   그리고 **가스 6종 각각 `|Δm| > 1%·max(m, 구값)` — 절대 하한 없음**.
3. **재구축.** `fillRadiationColumn` + `radiativeFluxes`로 전체 분광 솔버를
   돌려 longwave 계수와 층별 가열 계수를 다시 저장한다.
4. **적용.** 재구축 사이에는 저장 계수를 그대로 쓰고, 단편선은 현재 태양
   입사에 비례해 정확히 재확장한다(:643 주석 — 단파는 입사 플럭스에 선형).
   longwave 계수는 재구축까지 선형화된 채 적용된다.
5. **호출 지점.** `advance()`의 CFL 하위스텝 안에서 열 루프(:828–831)가
   표면 교환과 복사를 열 단위로 실행한다. `spectralScratch`는 인스턴스당
   하나라 단일 스레드 가정이 코드에 박혀 있다(:137).

구조적 사실 세 가지가 설계 공간을 결정한다.

- **선형화는 이미 계약의 일부다.** 재구축 사이에는 계수가 의도적으로 오래된다.
  나이 상한 300초는 모델이 스스로 허용한다고 선언한 최대 신선도 한계다.
  게임 dt 0.033초 × `AIR_SECONDS=60` = 물리 2초/스텝이므로 상한은 스텝
  약 150개다. 300초 안에 어떤 시점에 재구축하느냐는 물리 모델이 아니라
  수치 해법 매개변수의 선택이다.
- **무효화 규칙은 물리 법칙이 아니라 튜닝 상수다.** 1K, 2%, 1%, 300초는
  모두 선언된 허용 오차다. 가스 규칙만 절대 하한이 없어 수증기이론적 0에서
  증발이 시작되는 젖은 초기에 임계값이 0으로 수렴해 매 스텝 재구축을 강제한다.
  먼지·그을음에는 `1e-15` 하한이 있는데 가스에는 없다는 비대칭은
  "동량 가스 치환과 신규 흡수체 유입" 감지 의도(:650–651 주석)와
  함께 읽으면 과잉 트리거로 본다.
- **복사 스테이지는 열 독립적이다.** 열 루프는 자기 열의 층 배열과
  열 단위 슬롯(`energy[i*4]`, `roundoff[i]`, `absorbedSolar[i]`)만 쓰고,
  격자·태양 방향·solar 상수는 읽기 전용이다. 열 사이 수지 교환은 없다.
  `dynamics()`(에지 수송)만 열을 결합한다.

## 설계 원칙과의 정합

- "병렬 계산과 정밀도 차이에 따른 허용 오차는 별도로 명시한다" — 열 병렬화와
  재구축 일정 변경 둘 다 이 조항의 대상이다. 허용 오차와 검증을 문서화해야 한다.
- "혼돈적인 장기 궤적의 점별 일치와 통계적 일관성은 구별한다" — 무효화 시점을
  바꾸는 대안(A·B)은 점별 비트 일치를 포기하고 통계적 일관성으로 검증한다.
  계수 적용 경로를 바꾸지 않는 대안(C)은 비트 일치를 유지한다.
- "계산 불안정에 대한 온도 제한이나 재고 보정은 물리 법칙으로 취급하지 않고
  발생량을 드러낸다" — 임계값·예산·신선도는 수치 해법 매개변수로서 문서와
  진단 카운터로 드러낸다. 이미 `setRadiationDiagnostics` 카운터가 있고
  하니스가 기록한다.
- 수지: 재구축 시점은 적용 플럭스의 값만 바꾼다. 적용된 플럭스는 그대로
  표면·층·TOA 장부에 기록되므로 에너지 수지는 모든 안에서 정확히 유지된다.
  신선함(정확도)이 달라질 뿐 보존이 달라지지 않는다.

## 개선안

### A. 흡수 가스 무효화 임계값 개혁 (1순위)

**변경.** 가스 규칙을 상대 전용에서 복합 기준으로 바꾼다.
`|Δm| > max(floor_g, .01·max(m, 구값))`에 `floor_g`를 종목별 복사 중요도에
비례해 둔다. 더 정확한 형태는 광학 깊이 기준이다.
`Σ_band |Δm_g|·κ_g,band > ε_band` — 즉 "재고가 움직인 %"가 아니라
"이 두꺼비 변화가 솔버 입력을 얼마나 바꾸는가"로 판정한다. κ 표는
`ecckd-32`가 이미 갖고 있어 추가 상태가 없다.

- 치환 감지 의도는 보존된다. 동량 치환도 κ가 다르면 광학 깊이 변화가 0이
  아니므로(가스별 κ 상이) 여전히 잡힌다. 정말 κ가 같아 광학적으로 동등한
  치환은 재구축해도 결과가 같다 — 잡을 물리적 이유가 없다.
- 절대 하한은 먼지·그을음 규칙과 같은 형태라 구조 일관성도 맞는다.

**기대.** 재구축율이 마른 수준(측정 창에서 0%)으로 내려가면 젖은 복사 비용은
적용 비용 + 잔여 재구축으로 수렴한다. 재구축당 55µs, 호출당 6µs로
환산하면 [추정] 젖은 복사 658ms → 수십 ms. 스텝 전체로는 612ms(WASM 기준)에서
재구축 점유율만큼 감한다. 다만 측정 창이 초기 증발 상승 구간이므로
장기 젖은(soak) 재구축율을 먼저 재야 한다.

**계약 영향.** 점별 비트 일치 깨짐(재구축 시점 변화). 통계 검증 필요.
저장 형식 변화 없음(임계값은 코드 상수).

**검증.** (1) 하니스 카운터로 전/후 재구축율·트리거 분포 비교.
(2) `climate-soak-browser` 장기 젖은 통계, `science:held-suarez`, `science:rcemip`
기준 climates 통계 일관성. (3) 수지 장부(roundoff, energy, escaped) 정확성.
(4) 황금 상태(warm/cold/deep golden)는 재구축 시점이 바뀌므로 해당 스위트의
기대값 갱신이 필요한지 확인 — 나이 상한 300초에 걸리지 않는 짧은 골든은
불변일 수 있다.

**위험.** 임계값을 느슨히 하면 계수가 오래된다. 그러나 허용 상한은 이미
300초로 선언돼 있고, 단파는 태양에 선형, longwave는 층 온도 1K·질량 2%를
이미 허용하는 선형화다. ε는 이 기존 허용 오차와 정합되게 정한다.

### B. 재구축 예산 스케줄러 (2순위)

**변경.** 무효화 판정과 재구축 실행을 분리한다. 트리거는 "더티" 표시만 하고,
스텝당 예산 K개 열을 만료 순(나이+중요도)으로 재구축한다. 신선도 상한은
기존 나이 상한 300초를 그대로 쓴다 — 즉 어떤 열도 오늘 허용된 것보다
더 오래된 계수를 받지 않는다. 스케줄러는 상태만으로 결정적이다(같은 상태·
조건 → 같은 일정).

**기대.** 최악 스텝 복사 비용이 `K·55µs + count·6µs`로 상한 고정. K=64면
재구축 상한 ~3.5ms. 스파이크 제거 효과가 본체다.

**계약 영향.** A와 같이 점별 일치 깨짐, 통계 검증. 저장 재개 시 스케줄
큐는 캐시 나이·더티 판정으로 적재 시 재유도하므로 새 직렬화 상태가
필요하지 않게 설계한다(저장 형식 불변 유지).

**검증.** A와 동일 + 재개 동등성(같은 저장에서 이어 받으면 같은 일정).
+ 백로그 스트레스(모든 열이 매 스텝 더티)에서 신선도 상한 준수 확인.

**위험.** 지속적 더티(격변 상황)에서는 사실상 전 열이 상한 근처까지
오래된다. 이는 현재 모델이 선언·허용하는 범위 안이지만, 도구로 950°C를
넣는 직후처럼 급변 구간의 체감 정확도가 달라진다. 급변 열(도구 편집 직후)
에 우선순위 가중으로 완화한다.

### C. 복사 스테이지 열 병렬화 (3순위, 물리 불변)

**변경.** 복사 열 루프를 W개 워커가 SharedArrayBuffer 상태에서 분담한다.
열 독립성이 확인돼 있어(위 구조적 사실) 열당 산술을 전혀 바꾸지 않으면
결과는 순차 실행과 열마다 비트 일치한다. 페이즈 배리어(스테이지 시작·종료
`Atomics.wait/notify`)로 배타성을 보장하고, 워커당 `spectralScratch`를
준비한다. `dynamics()`는 순차 유지.

- 브라우저는 COOP/COEP 교차 출처 분리가 전제다. Cloudflare Pages 헤더로
  설정 가능하며, 미지원 환경은 기존처럼 순차 폴백(WASM 폴백과 같은 패턴).
- Node·vitest는 `worker_threads` + SAB로 같은 경로를 검증한다.

**기대.** 복사 구간 실시간 ÷ W. 4워커에서 [추정] 3배 내외(배리어·스케치
경합 차감). A 이후 복사 잔여분에 적용하면 젖은 스텝이 목표에 근접한다.

**계약 영향.** 물리 결과 불변 — `physics-performance-equivalence` 형식의
`Object.is` 열별 동등성 검사로 증명. 과학 재검증 불필요.
실행 경로 추가(워커 풀 수명, 실패 폴백, 장치별 분기)는 0.7.0 Worker·WASM
패턴의 재적용이다.

**검증.** (1) 순차 대비 열별 `Object.is` 동등성(전 시나리오).
(2) 저장 재개 후 병렬 경로 동등성. (3) 워커 실패·미지원 환경 폴백 회귀.
(4) CI 시간 예산 — GitHub 러너 타임아웃 이력이 있어 병렬 테스트 상한을
명시해야 한다.

**위험.** SAB 부재 환경 분기, 워커 풀 복잡도. 물리 불변 대신 실행
인프라 비용이 전부다. COOP/COEP는 배포 헤더 변경이므로 운영 문서와
함께 검증한다.

### D. 밴드 단위 부분 재구축 (후순위)

두 스트림 솔버는 밴드 독립적이다(WASM 커널도 밴드별 5 커널). 밴드별 플럭스를
캐시하고 광학 깊이가 임계 이상 변한 밴드만 재계산하면 재구축 비용 자체를
줄인다. 다만 캐시 레이아웃이 ×32로 늘고 `radiationCache` 직렬화 형식을
버전 올려야 한다. A·B·C로 목표에 못 미칠 때 검토한다.

## 권장 순서와 합성 효과

```text
측정(젖은 soak 재구축율) → A(임계값 개혁) → 재측정 → C(열 병렬화)
→ B(예산 스케줄러, 스파이크가 남으면) → D(밴드 부분, 그래도 부족하면)
```

근거 수치로 합성하면 [추정]: 젖은 2,562셀 스텝은 현재 612ms(CPU WASM)·
504ms(브라우저 Worker WASM)다. A로 재구축이 마른 수준이 되면 복사 구간이
수십 ms로 내려가 스텝은 비복사 비용(마른 기준 약 260ms + 젖은 고유 과정)에
수렴한다. C가 복사 잔여분을 워커 수로 나눈다. 33.33ms/스텝 목표까지는
비복사 구간(수송·열역학·상평형)의 병렬화와 기존 P2 항목(스테이지 국소 캐시)이
다음 단계다 — 이 연구는 복사 구조만 다룬다.

## 비목표

- GPU 상주 연산: 0.7.0에서 정확성·효익 미검증으로 배제한 결정을 유지한다.
- 복사 모델 교체(gray 전환, 밴드 수 축소): 물리 근사 변경으로 별도 과제다.
- Float64 재고·수지 정밀도 축소: 공통 실행 계약 위반.
- 무효화 임계값을 결과에 맞춘 사후 튜닝: ε는 기존 선형화 허용 오차(1K, 2%,
  300초)와 정합되게 도출하고 통계 검증으로 채택한다.

## 재현·측정 방법

```sh
# 기존 하니스가 카운터를 기록한다(optimization-cpu-harness.mjs:53).
node --expose-gc docs/performance/2026-10-23/optimization-cpu-harness.mjs
# 결과의 scenarios[*].radiationDiagnostics에서 재구축율·트리거 분포를 읽는다.
```

장기 젖은 재구축율은 `tests/climate-soak-browser.ts` 랩에 카운터 출력을
추가해 측정한다. 모든 대안은 적용 전후 카운터·스텝 시간·기후 통계를
같은 장비·같은 조건에서 비교한다. 0.7.0 때와 같이 다른 계산을 겹치지
않는다.
