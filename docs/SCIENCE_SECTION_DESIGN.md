2026-10-10 구현 상태: [P1과 실시간 단면](IMPLEMENTATION_VALIDATION.md), [P2 과학 규칙과 검증](P2_IMPLEMENTATION_VALIDATION.md). 아래 확장 제안 중 압력은 독립 대표 부피 대신 같은 정수압 기둥·몰분율 기준으로 구현했다. 복사/온실 모델과 물질별 확장 액상은 후속 범위다. 실제 구현 계약은 위 검증 문서를 따른다.


설계 개정 2026년 10월 10일. 사용자 확정 요구는 **같은 시뮬레이션 패널에서 구형 ↔ 단면을 연속적인 카메라 전환으로 보고, 단면에서도 기존 파우더토이 렌더와 도구를 실시간으로 사용하는 것**이다. 같은 행성·solver·tick·낙하 입자·명령 큐를 계속 실행한다. 단면을 그래프 패널이나 별도 예제 세계로 전환하는 안은 제품 설계에서 대체한다.

현재 구현 상태와 검증 범위는 [구현 및 검증](IMPLEMENTATION_VALIDATION.md)을 따른다. 아래는 제품 계약과 후속 과제를 포함한 설계다.

## 1. 첫 버전의 범위와 완료 조건

현재 2,562개 물질 기둥과 24필드 상태를 유지한다. 단면은 같은 행성의 절단 렌더다. 모드 전환이 물리·시간·재고·낙하 궤적을 바꾸지 않는다. 행성의 깊은 내부, 물질 층 순서, 지하 온도 분포, 공동, 부유 얼음판은 현재 상태에 없으므로 계산된 상태처럼 표현하지 않는다. 이 과학적 경계는 단면의 실시간 렌더와 기존 도구 지원을 줄이는 근거가 아니다.

기존 canvas의 카메라 모드에 ‘구형 / 단면’을 둔다. 단면의 주 화면은 잘린 행성의 물질과 입자이며, 온도·조성·수치 그래프는 보조 관측 기능이다. 물질 붓기, 가열, 냉각, 깎기, 회수, 기체 공급, 운석, 일시 정지, 배속을 첫 단면 출시부터 지원한다. 물·얼음·구름·비·눈·증기·열 효과·생태 표시는 같은 계산 결과를 매 렌더 프레임 그린다. 관측 전용 단면을 완성으로 처리하지 않는다.

현재 구현된 현상은 모두 단면 렌더에 연결한다. 향후 추가할 용융 이동·재용융·압력 반응도 같은 렌더 계약에 추가한다. 현재 없는 물리 현상을 단면에서 새로 발생한 것처럼 보이게 하지 않는다. 경계 유량·열수지 화살표는 실제 진단 데이터가 준비된 뒤 더한다. 기존 강수 지역 레이어와 같은 커밋의 비·눈 셀을 공유하며 kg/단계와 kg/게임초를 구별한다.

첫 출시의 통과 장면은 ‘물 붓기 중 단면으로 전환 → 같은 물방울 착지와 유출 관찰 → 단면에서 냉각과 가열 → 구형으로 복귀’다. 그 과정에서 화면을 비우거나 입자를 재생성하지 않고, 동일 명령이 한 번만 적용되어야 한다.

## 2. 같은 패널의 카메라와 입력

플레이어가 ‘단면’을 누르면 현재 선택 셀 또는 화면 중심의 표면을 지나는 중앙 절단면을 자동으로 잡는다. 두 점 선택을 필수 진입 절차로 두지 않는다. 선택한 표면을 중심으로 카메라가 옆으로 이동하고 가까운 반구가 절단되며, 같은 canvas 안에 단면이 드러난다. 카메라 자세·투영·절단 표시를 함께 연속 전환한다. 단면에서는 측면 직교 투영으로 선택 표면 주변을 확대한다. 두 축 절단면 회전을 기본 드래그 동작으로 하고, 이동 모드와 전체 단면 버튼을 별도로 제공한다.

전환은 solver 재생·일시 정지·배속과 독립적이다. 검은 화면, loading 화면, canvas 교체, 별도 render loop, 저장·복원·낙하 물질 합산을 사용하지 않는다. 돌아갈 구형 카메라의 자세·확대·관측 대상을 보관한다. 단면은 행성 로컬 좌표에 고정하며 자전 중에도 같은 절단 영역을 추적한다. 카메라와 clip plane이 현재 root 변환을 함께 따라가고 일조·공전·자전 계산은 계속 진행한다.

| 상태 | 가능한 동작 | 나가는 조건 |
| --- | --- | --- |
| globe | 기존 모든 도구, 단면 진입 | 단면 → enteringSection |
| enteringSection | 물리·입자 계속 진행, 현재 카메라와 절단 표시 전환 | section, 재전환 요청은 현재 자세에서 되돌림 |
| section | 기존 모든 도구, 이동·확대, 절단면 회전·재선택 | 구형 → leavingSection |
| choosingPlane | 구형의 A/B 또는 단면 각도 선택, 물질 입력과 구분 | 확정 → section, Esc → 이전 모드 |
| leavingSection | 물리·입자 계속 진행, 구형 카메라로 복귀 | globe, 재전환 요청은 현재 자세에서 되돌림 |

단면에서도 재료를 선택했을 때 왼쪽 드래그는 현재 물질 도구다. 그랩·오른쪽 드래그·두 손가락 동작·조이스틱·방향키는 기본적으로 절단면을 두 축으로 회전한다. 화면에 표시된 이동 버튼으로 평행 이동을 선택하며 Shift+드래그는 임시 이동이다. 휠·핀치는 확대한다. 절단 방향과 기울기는 행성 조정의 두 슬라이더로도 바꿀 수 있다. 현재 선택 도구·물질·공급량·붓 크기를 유지한다. 전환 중 이어지는 브러시 획은 기존 행성 로컬 목표를 유지하고, 새 획은 현재 카메라의 picking으로 시작한다. 기존 pointer capture를 끊어 동일 명령을 재발행하지 않는다. 키보드는 모드 전환·카메라 이동·관측 셀 이동을 제공한다.

데스크톱과 모바일 모두 기존 시뮬레이션 패널 전체가 단면으로 전환한다. 하단 280px 그래프 영역이나 두 번째 canvas를 주 화면으로 추가하지 않는다. 기존 도구·재생 컨트롤·관측 패널을 재사용한다. 선택 지점의 온도·조성 그래프는 필요할 때 보조 패널에 연다. reduced motion에서는 전환 애니메이션만 즉시 완료하고 물리 tick을 건너뛰지 않는다.

기존 Sandsphere의 셸·물질 의미색·조명·재질을 유지한다. 단면 전용 자료 뷰어를 게임의 시각 시스템으로 대체하지 않는다. 같은 선택 셀을 구형과 단면에서 강조한다.

## 3. 중앙 절단면과 셀 대응

절단면은 행성 중심을 지나며 행성 로컬 좌표의 법선 n과 화면의 두 축 u,v로 저장한다. 기본 단면은 현재 선택 방향 p와 표면 접선 t를 포함하며 `u=t, v=p, n=normalize(t×p)`다. p와 t가 안정적인 기저를 만들지 못하면 카메라의 다른 접선을 사용한다. 단면에서 법선 방향으로 두께를 가진 표시 띠를 사용해 유한 크기의 물질 셀과 입자를 볼 수 있게 한다. 이 두께는 표시 범위이며 물리 차원을 2D로 바꾸지 않는다.

물질 기둥의 절단면과 기존 구면 메시를 같은 원래 상태에서 만든다. 고체·액체의 잘린 면을 새로 생성해야 하며, 카메라 회전만으로 표면 메시의 속이 채워지지는 않는다. 구현의 좌표·clip·메시·입력 계약은 [단면 카메라 렌더 명세](SECTION_CAMERA_RENDERING.md)에 정의한다.

구형에서 A/B로 절단면을 지정하는 것은 선택적 기능이다. 두 단위 방향 a,b에 대해 `n=normalize(a×b)`, theta=acos(clamp(dot(a,b),-1,1)). A/B가 정한 중앙 평면은 전체 대원을 나타내고 A→B는 관측·확대할 구간이다. 0.5° 미만 또는 175° 초과는 불안정한 A/B 지정으로 처리하고 다른 점을 안내한다. 이 제한으로 전체 원형 단면 자체를 금지하지 않는다. 평면과 u,v가 정해졌다면 전체 경로는 `d(phi)=u cos(phi)+v sin(phi)`다.

```text
d(t) = [sin((1-t)theta) a + sin(t theta) b] / sin(theta), 0 <= t <= 1
```

초기 샘플 간격은 해당 그리드의 최소 이웃 각거리의 1/4 이하로 한다. 각 d(t)를 nearestCell에 대응하고 인접한 동일 cellId 구간을 합친다. 셀 경계 근처는 재샘플링하며 연속 구간의 셀 전환이 실제 이웃인지 검사한다. 비인접 전환이 남으면 해당 간격을 더 세분한다. 경계 접촉처럼 여러 셀이 같은 최대 내적을 갖는 경우 안정적인 cellId 순으로 판정한다. 샘플링은 관측을 위한 대응이며 물리 격자를 세분화하지 않는다.

단면의 각 원래 물질 기둥에 owner cellId를 붙인다. 시각 보간과 grain 표현을 사용해도 조성·편집·가열은 원래 셀에 대응한다. 한 셀이 여러 절단 구간에 나타나면 합계·브러시 처리에서 unique cellId로 중복을 제거한다. 단면 합산값은 ‘절단면에 걸친 셀 합계’로 명명한다.

주 화면은 곡률을 유지한 원형 또는 확대된 표면 호 단면이다. 각거리(°)·모델 높이는 측정 도구와 보조 그래프에서 읽는다. 현재 HEIGHT_SCALE·시각 반지름·ESCAPE_MODEL_RADIUS를 실제 m·km로 환산하지 않는다. kg은 기존 게임 단위다. 확대와 표시 높이 압축은 양쪽 카메라에서 동일한 함수로 처리하고 관측 수치는 원래 셀값을 읽는다.

## 4. 높이와 조성의 표시 계약

각 셀에서 아래 값을 직접 읽는다.

```text
baseHeight = grid.geometry[4i+3]
solidTop = solidHeight(state,i,grid)       # 현재 solver가 사용하는 높이, 얼음 포함
hydraulicHead = solidTop + water
heldWater = min(water, min(1.2, soil * 0.12))
mobileWater = max(0, water - heldWater)
iceMass = state[24i+F.ice]
columnTemperature = state[24i+F.temperature]
```

단면 고체는 기존 재질과 현재 조성으로 그린다. 모래·점토·도자기·유리·소금·용융·토양·운철·암석·얼음의 양과 온도 변화를 절단 기둥의 혼합 색·입자 무늬·열 효과로 표현한다. 무늬는 현재 물질 조성의 표현이며 층 순서나 낱개 입자 위치가 저장되었다는 뜻이 아니다. 현재 상태에 없는 퇴적 순서를 깊이별 띠로 만들지 않는다. 조성 막대는 보조 목록의 질량 비율이다.

`solidTop`에서 액체 물의 수두까지를 같은 물 재질로 렌더한다. 얼음은 현재 고체 높이에 기여하는 상으로 표시하고 별도 부유층으로 옮기지 않는다. 보유수는 액체 물의 부분집합이며 중복 집계하지 않는다. 현재 구형의 얼음·보유수 시각 처리는 이 공통 경계와 다르므로 공유 geometry 생성 단계에서 함께 정리한다. 두 모드가 다른 수면·접촉 높이를 쓰는 상태로 출시하지 않는다.

baseHeight 아래는 고정 기반의 중립적인 절단 면으로 채우고 비편집 영역을 구별한다. 이 경계는 실제 지각 두께나 맨틀·핵 상태를 뜻하지 않는다. 수증기·구름·생물량을 지형 두께로 더하지 않는다. 기존 기체·구름·비·눈·증기·생태 렌더는 해당 지점의 효과로 계속 보인다. 구름의 표시 높이는 기존 대표 상층 모델의 시각 척도이며 계산된 수직 밀도·온도장을 뜻하지 않는다.

온도 모드에서는 같은 셀의 대표 온도를 절단 기둥에 적용한다. 임의의 깊이별 온도 변화를 만들지 않는다. 보조 온도 그래프와 대표 상층 T−12°C 표시는 별도로 제공할 수 있다.

## 5. 공통 상태와 진단 API

구형과 단면은 마지막 커밋된 solver 상태 및 같은 geometry·낙하·효과 frame을 읽는다. 단면만 저장용 `snapshotSurface()`를 읽거나 별도 CpuSolver를 만들지 않는다. GPU readback 중에는 이전 commitId를 유지하며 부분적으로 새 데이터를 섞지 않는다. 카메라 전환을 위한 렌더 메시·인스턴스 캐시는 만들 수 있지만 복제된 시뮬레이션을 실행하지 않는다.

```ts
interface ObservationFrame {
  planetId: string;
  commitId: number;
  tick: number;
  modelRevision: string;
  state: Float32Array; // 소비자는 읽기 전용; 커밋 동안 수명 보장
  environment: Environment;
  diagnostics?: StepDiagnostics;
}
interface SectionSelection {
  planetId: string;
  normalLocal: [number,number,number];
  uLocal: [number,number,number];
  vLocal: [number,number,number];
  halfWidth: number; // 표시 띠; 장면 단위, 물리 격자 두께 아님
  arc?: {a: [number,number,number]; b: [number,number,number]};
  pinnedCellId?: number;
}
```

`StepDiagnostics`는 커밋에 연결된 dt, 반응별 kg 이동, 태양·복사·도구·전도·물질 유입출의 열량, 에너지 잔차와 경계별 수송량을 포함한다. CPU와 WGSL은 같은 의미·부호·단위를 사용한다. GPU 진단은 단면 선택 셀만 또는 저주기 전체 버퍼로 읽어 비용을 제한한다. 진단이 없으면 해당 표시를 숨기고 이전 화살표를 새 시간의 값으로 재사용하지 않는다.

유량 단위는 kg/게임초다. dt=0의 명령 적용에서 유량을 나누어 계산하지 않는다. 비활성 행성을 여러 tick으로 묶어 계산한 경우 진단은 마지막 tick 값 또는 명시된 기간의 누적량으로 구분한다. 점선 방향 화살표를 태양 방향·바람 근사에 쓰더라도 실제 경계 유량 화살표와 범례를 다르게 한다.

제안 모듈은 `src/sim/clock.ts`(공통 진행), `src/sim/falling.ts`(공통 낙하 상태), `src/sim/diagnostics.ts`(관측량), `src/sim/section.ts`(절단 기저·셀 대응), `src/render/geometryFrame.ts`(공통 지형 경계), `src/render/section.ts`(Babylon 절단면·물질 렌더), `src/render/viewTransition.ts`(연속 카메라), `src/ui/section.ts`(모드 입력)다. SVG는 보조 그래프에만 사용한다. 이 목록은 구현 예정이며 현재 파일이 있다는 뜻이 아니다.

## 6. 시간과 명령 설계

기본 물리 단계 h는 1/60게임초를 시작값으로 한다. 1/30과 1/120의 수렴·성능 검증을 통해 출시값을 확정한다. 배속은 h를 키우는 방식 대신 실행할 tick 수를 바꾼다. 활성/비활성 행성·낙하 입자·공전·자전·반응은 동일한 h와 tick을 사용한다. 비활성 행성은 화면 업데이트를 5Hz로 줄여도 내부에서는 같은 작은 tick을 계산한다.

작업 큐는 미래 tick에 입력을 배정하고 GPU 계산은 한 배치를 커밋한 뒤 다음 배치를 시작한다. 처리량을 넘으면 전 세계의 게임 시간 진행을 함께 늦추고 ‘계산 중’ 상태를 표시한다. 화면 프레임에서 버린 시간을 물질 공급만으로 보상하지 않는다. 숨겨진 탭과 앱 종료 중에는 새 tick을 만들지 않는다. 미래 구현의 최대 배치 수와 렌더 readback 주기는 성능 실험에서 정한다.

명령은 `(sequence, targetTick, planetId, cellId, operation, payload)`로 정의한다. 붓기의 kg/게임초는 공통 tick에서 적분한다. 표면·단면의 브러시는 같은 구면 brushWeights를 호출하며 단면 구간 수에 따라 공급량을 곱하지 않는다. 낙하 물질은 공급 시 외부 장부·재고에서 한 번 빠지고 착지 시 표면으로 옮겨진다. 렌더 입자가 착지 명령의 권한을 갖지 않게 낙하 상태를 sim 모듈로 옮긴다.

정지 중에는 카메라와 관측이 가능하다. 편집은 클릭·브러시 이동에 명시된 횟수·양으로 적용한다. 계속 누르고 있는 화면 시간에 따라 무한 공급하지 않는다. 열 도구는 해당 셀에 필요한 에너지를 한 명령으로 넣고, 자연 상변화는 다음 tick에 실행한다. 정지 중 편집 뒤에는 ‘편집 적용 · 다음 단계에서 반응’ 상태를 표시한다. 한 단계 진행은 h를 정확히 한 번 수행하고 다시 정지한다.

## 7. 열수지와 상변화

게임 열량의 기준은 0°C의 액체 물과 물질별 상수 비열 모델로 시작한다. 현재의 공통 바탕 열용량 28은 유지하되 내부 기반의 상세 물성을 뜻하지 않는 보정값임을 기록한다.

```text
E_i = C_base T_i + Σ_f m_if [cp_f T_i + ell_f]
E_after = E_before + Q_external + Q_in - Q_out
```

물 이동은 현열뿐 아니라 해당 물질의 기준 엔탈피를 함께 이동한다. 전체 경계의 수송은 쌍으로 상쇄한다. 상변화는 물질량 변경 후 같은 E로 새 T를 풀며, 상태 경계에서 부분 변환량을 결정한다. 물의 기존 상수로는 ell_water=0, ell_ice=-334, ell_vapor=2257+(4.18−2)*100=2475를 사용할 수 있다. 구름 물과 얼음은 해당 물 상과 같은 기준을 사용한다. 값은 현재 게임의 비열 근사와 일치시키기 위한 출발점이며 광범위한 온도·압력에서의 실측 상태식은 아니다.

염수 동결은 염분 변화와 어는점 이동을 작은 내부 반복으로 처리한다. 농축 염수의 화학퍼텐셜까지 생략한다면 ‘염분 경계는 게임 근사, 열량은 선언된 기준으로 보존’이라는 계약을 택한다. 음수·온도 클램프가 필요할 때는 수정량을 residual로 기록하고 반복 단계 축소·입력 제한으로 원인을 해결한다.

점토 소성은 반응 진행률을 물질량 이동에 연결하고 반응 에너지 q_firing을 명시한다. 초기 구현은 q_firing=0인 게임 보정으로 시작할 수 있으나 실측 점토 반응열이라고 표시하지 않는다. 용융과 유리는 기준 엔탈피 정책을 하나로 확정한 뒤 재가열 경로를 만든다. 고정 잠열이 없는 유리 모델을 택하면 별도 유리화 열 이력을 사용하고, 단순 상전이 모델을 택하면 임계값·엔탈피 차이를 게임 규칙으로 문서화한다. 출시 전에 두 모델 중 하나를 선택하고 검증한다.

공유 보관함은 질량과 함께 에너지를 보존하거나 ‘표준 상태로 조정’하는 외부 열 교환을 기록한다. 첫 확장은 물질별 표준 공급 온도(얼음은 0°C 이하)와 외부 열 장부로 한다. 현재 모든 공급물을 20°C로 취급하는 동작은 새 규칙의 공급 계약으로 그대로 사용하지 않는다. 가열 도구의 목표 온도는 새 상태의 열용량으로 계산하고 GPU 대기 중 같은 목표에 대한 에너지를 중복 누적하지 않는다.

## 8. 환경과 재질 확장

압력 상변화는 기압 1×를 P_ref=101325Pa에 대응하는 게임 보정으로 도입한다. 실제 행성 질량·면적으로부터 산출한 값이라고 표현하지 않는다. 대표 공기 부피 V_ref를 정하고 같은 몰수 기준으로 수증기 부분압을 계산해 포화 증기압과 비교한다. 압력을 표시하는 식과 응결식이 동일한 기둥 모델을 사용해야 한다. 삼중점 아래·임계점 위는 액체 끓는점 표를 외삽하지 않는다. 지원 범위 밖은 별도 단순화 규칙을 정의하고 표시한다.

포화량의 kg 기준을 기존 0.5kg 함수에 다시 맞출지, 새 대표 부피에 맞춰 바꿀지는 이전 저장과 물 순환 속도 비교로 결정한다. 낮은 기압에서 끓는점 하강, 총 물 보존, 잠열 냉각을 먼저 검증한다. 증발률에 면적·바람·습도를 모두 도입하는 것은 별도 확장이다.

복사 모델은 `Q_net = Q_shortwave + Q_longwave_down - Q_longwave_up + Q_conduction + Q_tools`로 교체한다. `Q_longwave_up`에 Kelvin의 4제곱을 쓰고, 대기 조성의 광학 두께는 보정된 계수로 묶는다. 지표와 대기 에너지의 독립 상태를 도입하기 전에는 복사 피드백을 유효 기둥 모델로 명명하고 밤의 역복사를 실제 대기층 계산처럼 표시하지 않는다. 모델 기준량과 게임 시간 보정값이 정해지기 전까지 임의 계수를 출시값으로 고정하지 않는다.

소성물·유리·운철의 첫 역할은 열전도 차이와 재용융에 한정한다. 전도는 `Q_ij = k_ij (T_j-T_i) h`, `k_ij=k_ji`를 지켜 전체 열량을 보존한다. 다른 열용량에서는 explicit 안정성 한계를 확인하고 필요하면 내부 단계를 더 나눈다. 투명 덮개는 층 순서·피복 배치 상태 없이 임의로 모든 아래 물질의 일조량을 바꾸지 않는다.

소비자 생물량은 온도·액체 물·염분·빙결에 따른 환경 사망률과 이동 적합도를 사용한다. 생물량·토양으로의 반환은 내부 장부를 보존한다. 광합성 CO₂·O₂ 수지는 이 단계의 필수 범위가 아니다. 구름을 통과한 일조량은 열·식생·관측에서 동일한 값을 사용한다.

## 9. 체크포인트와 이전 저장

체크포인트 단위는 항성계 전체다. 행성 하나만 되돌리고 공유 재고·생물 보상은 남기면 재고 복제가 가능하므로 함께 복원한다. 행성 상태, 재고, 탐사 진행, 공급·회수·탈출 장부, tick, 낙하 위치·속도·명령·난수 상태를 같은 커밋 경계에서 저장한다. 관측선·카메라는 표시 환경으로 별도 저장해도 된다.

modelRevision을 저장 envelope에 추가한다. 단면 관측 자체는 기존 24필드 저장의 변환을 요구하지 않는다. 새로운 물리 규칙은 새 세계에 먼저 적용한다. 기존 세계는 0.3 규칙으로 읽고 실행하며, 새 규칙으로 실험하려면 ‘새 규칙으로 복제’가 별도의 세계 사본과 원본 백업을 만든다. 원본 물질량·온도를 자동 변환하지 않는다. 복제 시의 엔탈피는 저장된 T·m와 선택한 새 물성표에서 명시적으로 초기화하며 역사적 에너지가 복원되었다고 주장하지 않는다.

표본을 포함한 세계 복제는 공유 보관함으로 생산물을 중복 회수하는 우회로가 될 수 있다. 첫 출시에서는 체크포인트 복원으로 반복 실험을 제공하고, 독립 세계 복제는 별도 실험 슬롯과 별도 재고를 갖도록 한다. 기존 네 행성 한도에서 실험 슬롯이 행성 수 제한을 차지하지 않도록 분리한다.

주 렌더는 기존 render loop의 매 프레임 갱신한다. 지형과 절단 면은 solver 커밋마다 갱신하고 입자·카메라는 해당 프레임의 공통 상태를 보간한다. 10Hz 제한은 선택 셀의 숫자·보조 그래프에만 적용할 수 있다. 렌더를 10Hz 자료 화면으로 대체하지 않는다. 동일 네 행성·배속·입자 조건에서 전환과 steady-state의 frame time, 지형 갱신·GPU readback 비용을 비교해 성능 기준을 확정한다. 저성능 장치에서는 보조 효과 밀도부터 줄이고 물리·명령·셀량을 바꾸지 않는다.

## 11. 이전 수치 시안의 지위와 다음 구현

`design/science-section.html`은 원래 셀 수치와 축·단위·조성을 확인하는 이전 자료다. 별도 예제 세계와 미리 계산한 시간 슬라이더를 사용하므로 **현재 확정된 단면 카메라의 제품 시안이나 구현 완료 근거가 아니다**. 본 앱의 저장소·공유 재고에 접근하지 않는 수치 자료로 보존한다.

`node design/generate-section-preview.mjs`는 이 수치 자료를 재생성한다. 다음 제품 구현은 본 앱의 `PlanetView`·단일 render loop·공통 command controller 안에서 수행한다. 첫 제품 시연도 같은 실행 중인 세계에서 카메라 전환과 모든 레이어·도구를 확인해야 한다. 별도 데모에서 비슷한 입자를 새로 만들어 보여주는 것으로 대체하지 않는다.

### 이전 수치 자료의 검증 기록

실제 데이터로 생성한 3개 관측선은 각각 35·23·17개 셀을 지나며 연속 구간의 셀 인접성을 검사했다. 총 73개 고유 셀, 0·2·4·8·16·32게임초의 6개 기록을 포함한다. 브라우저에서 관측선 변경, 다음/처음 기록, 키보드 셀 이동, 그래프 클릭 선택을 확인했다. 375px·768px·1440px 화면의 가로 넘침과 그래프 크기를 검사했다. 200% 브라우저 확대와 실제 터치 입력은 후속 구현의 검증 항목으로 남는다.

수치 자료는 로컬 HTML과 CSS·JavaScript, 내장 예제 데이터로 동작한다. 이 수치 자료 자체는 기본 앱의 단면 카메라가 아니다. 이후 기본 앱에 연결한 실시간 카메라·렌더·편집의 실행 검증은 [구현 및 검증](IMPLEMENTATION_VALIDATION.md)에 별도로 기록했다.


## 2026-10-10 기본 관찰 방식 변경

기본 단면은 국소 셀 범위를 수평으로 펼치고 기반암을 숨긴다. 물리 상태는 구면에 유지하며 표면 혼합물과 액체·대기·입자 렌더를 동일 변환으로 표시한다. 세부 구현과 최신 검증은 [펼친 단면 검증](FLAT_SECTION_VALIDATION.md)을 참조한다. 이전의 원형 전체 단면 설명은 과거 설계 기록이다.
