# 표면층 단면 작업 화면

2026-10-11. 기반암 위의 물질을 크게 펼쳐 보고 공급·가열·냉각·깎기 실험을 이어갈 수 있도록 단면 표시를 수정했다.

## 표시와 조작

- 기반암 위의 고체 혼합층과 자유 물층을 세로로 확대한다. 기본 자동 맞춤은 가장 두꺼운 관찰 층을 화면 높이의 약 34%로 표시한다. 바닥은 화면 아래쪽에 두어 위에 공급할 공간을 남긴다.
- `층 확대`에서 자동 또는 1–64×를 선택한다. 가로 관찰 범위와 세로 배율은 분리한다. 자동 배율은 진입·범위 변경·범위 맞춤·창 크기 변경 때 정하며, 물질이 늘 때마다 배율을 줄여 성장을 감추지 않는다. 빈 기반에는 가짜 층을 만들지 않고 첫 물질이 들어왔을 때 맞춘다.
- 확대된 물질 위의 공중 공간은 추가로 늘리지 않는다. CPU 선택 좌표, GPU 표시, 공급 입자, 기후 지도와 흐름 화살표가 같은 변환을 사용한다.
- 입자 칸은 실제 고체 재료의 질량 비율에 따라 색을 배정한다. 약 5 CSS px 크기로 보여주며 물질 경계 자체는 기존 연속 표면을 유지한다.
- 단면의 깊이 분포에서도 기반암을 제외한다. 단면의 깎기는 표면 물질을 제거하며 숨긴 기반암과 대기·구름 저장량을 보존한다. 제거 질량 집계 및 저장 직전의 대기 명령 정산에도 같은 규칙을 적용한다. 구면의 기존 깎기 동작은 유지한다.
- 좁은 화면에서는 회전·이동·범위 맞춤을 첫 줄로, 관찰 범위와 확대 선택을 다음 줄로 묶는다. 지도 선택기는 그 아래의 공중 공간에 둔다.

### 현재 물리 모델의 범위

현재 각 구면 셀은 하나의 균일한 고체 혼합 저장층과 자유 물층을 계산한다. 화면의 작은 입자 칸은 독립적으로 저장·충돌·열 교환하는 세로 물리 셀이 아니다. 퇴적 순서나 존재하지 않는 재료별 지층을 그려 넣지 않았다. 서로 다른 깊이의 작은 칸을 선택해도 같은 구면 셀에 해당하면 같은 혼합물을 편집한다. 독립적인 세로 셀과 퇴적 이력을 도입하려면 상태·수송·열 교환·GPU 계산·저장 모델을 별도로 확장해야 한다.

## 검증

- `npm test`: **246 통과, 14 제외**. 계정 에뮬레이터 및 별도 실행하는 장시간 검사는 기본 실행에서 제외된다.
- `npm run build`: TypeScript 및 배포용 빌드 통과. 기존 대형 번들 경고는 남아 있다.
- WebGPU / WebGL: 각 렌더러에서 최초 방향 122개, 회전·기울기 변경 후 168개 실제 단면 삼각형의 화면 선택이 물리 소유 셀과 일치했다. 4× 수동 확대, 공중 공급 위치 왕복, 기반암·관찰 범위 밖 선택 차단, 구면 복귀, 상태·질량·엔탈피 보존도 통과했다.
- 두 렌더러 × 구면/단면 × 10개 지도 = **40가지 표시 조합**. 셀별 지도 색, 단면 색, 기류·해류 화살표의 공유 좌표 변환과 셰이더 준비 상태가 일치했다.
- 실제 공중 선택 → 공급 → 중력 낙하 → 물리 명령 → 갱신된 단면 → 깎기 경로를 검사했다. 공급량 2 kg 전량 착지, 남은 공급 질량 0, 기반암 보존. 자연 탈출량까지 포함한 질량 오차 약 0.0000965 kg.
- 새 표면 깎기의 CPU/GPU 비교: 최대 온도 차이 0.00000954°C, 물질 필드 차이 1.19e−7. GPU 상태와 기후를 JSON 직렬화해 CPU로 복원한 뒤 30단계를 GPU 연속 실행과 비교했다. 복원은 정확했으며 최대 상태 차이 0.00006294, 총질량 차이 0.00000284 kg.
- 실제 GPU의 기존 과학 경계 20가지(염수, 소성, 용융, 강수, 생태, 탈출, 전도 등) 검사도 통과했다.
- 제품 화면의 배율 8× 도달값은 7.999999999999998, 정지된 세계의 질량 26388.600148141384 kg은 배율 변경 전후 동일했다.
- 렌더 검사에서 발견한 WebGPU 버텍스 버퍼 한도 초과는 사용하지 않는 법선 속성을 제거해 해결했다. 공유 기후 화살표 재질을 단면 재질 설치 과정에서 교체·폐기하던 문제도 수정했다.
