## 1단계 — 무손실 저장과 중복 작업 제거

- 길이가 긴 숫자 배열을 IEEE-754 Float64 이진 포장 후 gzip으로 저장한다. 재고·기후 캐시·관측 숫자를 양자화하지 않는다. 모델 저장 v11·대기 v6, 64MiB 원문·20MiB 압축 한도, 계정 충돌·리비전 규칙은 유지한다.
- 새 코드는 이전 gzip JSON과 IndexedDB 객체 저장을 계속 읽는다. 새 형식은 이진 전송 포장 버전이며 이전 앱이 새 포장을 읽는 역방향 호환성까지 제공하지는 않는다.
- 현재 v11 상태에 불필요한 Float32 변환·깊은 대기 이중 복사를 줄였다. 음수 반올림 수리가 필요한 저장은 기존 마이그레이션 경로를 사용한다.
- 정산할 명령·낙하가 없는 세션은 그림자 기후 계산기를 새로 생성하지 않고, 저장마다 활성 행성을 두 번 정산하던 경로를 한 번으로 합쳤다.

## 2단계 — 비동기 저장 준비·분할 실행·전체 관측 이력

- 자동 저장의 검증·마이그레이션을 별도 Worker로 보낸다. 메시지는 복사한 무손실 이진 버퍼로 전달하며 살아 있는 계산 버퍼를 detach하지 않는다. 검증 오류는 거부하고, Worker 생성·통신 실패는 보존한 캡처로 기존 검사 경로에 복구한다.
- 저장을 기다리는 동안의 새 물리 단계와 관측 표본이 과거 저장 장부에 섞이지 않게, 세계와 telemetry 에너지·이력을 같은 완료 시점에서 고정한다.
- 숫자 포장·해제는 짧은 작업으로 나눠 UI 스케줄러에 실행 기회를 준다. 변경 없는 정지 상태는 반복 저장을 생략하고, 0시간 편집 등 상태 revision과 환경·회전·재고·과제·관측 메타데이터가 달라지면 다시 저장한다. 원격 동기화나 IDB의 실제 프레임 지연은 아직 브라우저에서 측정하지 못했다.
- Float64의 바이트 순서를 무손실 재배열하고 관측 숫자 열의 키를 공유한다. 첫 이진 포장(v1)과 JSON 읽기를 유지한 v2 전송 포장이다. 스냅샷 모델 형식·재고·캐시는 바꾸지 않는다.
- 8개 진행한 목성은 gzip 약 **12,564,200B**로 저장됐다(같은 14단계 조건, 메타데이터 길이에 따라 수십 바이트 차이). 이전 21,306,431B 대비 약 41% 감소했다.
- **각 행성 2,048개 표본 × 8행성**의 최대 보관 이력을 넣은 합성 저장도 gzip **13,919,879B**, 원문 이진 포장 **52,340,104B**로 기존 한도 이내였다. 전체 숫자·null·이력 JSON 비교와 저장 후 정확한 물리 재개가 통과했다. 이력은 재현 가능한 합성 값이며, 장기 기후 계산을 2,048게임초 실행했다는 뜻은 아니다. 임의의 고엔트로피 유효 데이터 전체에 대해 압축 한도를 보장하는 결과도 아니다.
- Worker 캡처·실패 복구·잘못된 입력 거부·장부 고정·이전 포장과 IDB 호환 등 **27개 검사**, 확장한 저장 코덱 **6개 검사**, TypeScript·버전 검사가 통과했다. 실제 브라우저 Worker/GPU는 미검증이다.

증거: `stage2-save-metrics.json`, `stage2-tests.json`, `max-history-tests.json`, `max-history-metrics.json`.

## 3단계 — 대기·공통 열역학 처리량

- 에너지·열용량에서 실제 0계수만 건너뛰고 나머지 항의 순서를 유지한다. 수송 중 바뀌지 않는 층 에너지를 해당 단계에서 캐시하고 commit 뒤 다시 계산한다. 깊은 대기는 고정 접평면 기하·열압력 값을 공유하고 벡터/흐름 임시 객체를 재사용 버퍼로 바꾼다.
- 반응 데이터의 최저 점화 온도 이하에서는 불필요한 반응 경로 생성을 줄이되, 기존 무반응 에너지 역산과 운동량 반올림을 유지한다. 시간 간격·CFL·법칙·재고·복사 캐시 갱신 기준은 바꾸지 않는다.

구현 직전과 같은 하네스의 정상 8단계 평균(각 조건 독립 초기화, 준비 2단계):

이것은 CPU 소스 실행의 개선이다. 여전히 1× 목표의 33.33ms보다 길며 실제 브라우저 FPS·GPU 처리량을 달성했다고 해석하지 않는다. 측정 표본이 작고 장기 상태의 CFL 변화는 별도 검증 대상이다.

## 4단계 — 배경 상태 게시·미사용 대기 메모리·제한 동시 실행

- 실제 앱의 비동기 배경 경로는 완료 시점의 typed 상태를 보존하고, 일반 저장 배열을 읽을 때 한 번만 변환한다. 이후 솔버가 버퍼를 재사용해도 이전 게시 상태와 시간이 유지된다. 오프라인 동기 API의 기존 참조 갱신 계약은 보존했다.
- 일반/깊은 대기를 실제로 사용할 때만 할당하고, 미초기화 대기 체크포인트는 빈 버퍼·메타데이터로 표현한다. 상태 확인·진단만으로 미사용 대기를 만들지 않는다. 그을음 복사 2개 배열도 transfer 목록에 넣었다.
- 배경 작업은 최대 2개씩, 활성 계산과 독립적으로 실행한다. 오류가 있어도 현재 묶음의 모든 작업이 끝난 뒤 반환한다. 각 행성의 시간 단계·법칙·완료 상태와 실패 시 재시도는 유지한다.

2,562셀 젖은 해안의 일반 기후 snapshot은 14.42ms, 지연 typed 캡처는 0.30ms였다. CPU Solver 고유 typed 버퍼는 일반 대기 21.66→14.84MiB, 목성 21.66→13.21MiB, 기후를 끈 대조군 21.66→3.95MiB였다. JS 전체 힙·GPU 메모리나 누수를 측정한 값은 아니다. 이 변경 뒤에도 7조건의 유효 상태 해시가 변경 전과 일치했다.

`benchmark-workers.mjs`는 실제 Node worker_threads에 브라우저 솔버 번들을 CPU 강제로 올려 실제 메시지·버퍼 전달을 검증한다. Mac UI나 GPU에는 접근하지 않는다. wet·Jupiter의 직접 CPU와 Worker 결과 및 3행성 순차/동시 실행의 완료 결과가 모두 정확히 일치했다. 이벤트 루프 간격과 처리량의 수치는 동봉 `node-workers.json`을 따른다. 이 값은 브라우저 프레임·실기 GPU 검증을 대신하지 않는다.

이전 오프라인 동기 참조 계약을 검출한 2개 회귀를 수정한 뒤 관련 30개 검사(배경·Worker·장부·참조)가 통과했다. 그 외 배경 광범위 실행에서 통과한 보존·저장·행성 검사와 함께 최종 전체 회귀를 다시 수행할 예정이다.

## 5단계 — 의존성·렌더 업로드·관측 DOM

- Firebase는 타입/순수 설정 검사와 실제 SDK 로드를 분리했다. **설정 없는 게스트 빌드**는 SDK를 평가하지 않는다. 설정이 있는 앱은 인증 상태를 먼저 확인한 뒤 저장 범위를 고르는 기존 순서를 지킨다. 따라서 운영 설정이 있는 앱의 첫 부팅에서 SDK 전송 자체가 사라졌다고 주장하지 않는다. SDK 로드 실패는 기존 계정 오류 처리로 전달한다.
- ecCKD 원본 계수는 처음부터 Float32다. 같은 비트의 Float32 뷰를 읽고 정규화 가중치·계산 결과는 Float64를 유지한다. 디코딩한 계수 저장은 **3,321,456→1,660,728B/실행 영역**이다. 계수표 디코딩을 실제 사용까지 미뤄 유효성 검사 전용 저장 Worker에서는 표 전체가 제거됐다. 일반 계산용 main/solver Worker에 필요한 표의 중복 전송까지 제거한 구현은 아니다.
- 환경 파일을 읽지 않은 동일 빌드의 앱 정적 import 그래프는 **5,185,697→4,619,035B**, 개별 gzip 합 **2,205,347→2,038,698B(7.6% 감소)**다. CSS·폰트·동적 로드는 제외한다. 새 저장 Worker는 **37,363B / gzip 13,575B**다. 초기 구현에서 불필요한 표를 포함한 2.26MB Worker가 검출돼 이를 제거했다. 총 배포 파일 수나 모든 기능을 사용한 총 다운로드가 같은 비율로 감소한다는 뜻은 아니다.
- 지형·물·열의 9개 버퍼는 마지막 전송값과 **Float32 비트 단위**로 비교한다. 바뀐 버퍼만 업로드하고, 해안은 위치/인덱스가 달라질 때만 노멀·메시를 재생성한다. 해안의 사라짐/재등장, 속성만 변경되는 경우도 처리한다. 앱이 직접 수행하는 picking은 유지하고 Babylon의 중복 pointer-move picking을 끈다.
- 관측 텍스트는 현재 언어로 변환한 값이 바뀔 때만 DOM에 쓴다. 물질 구성 행은 행 수가 같으면 재사용한다. 선택 셀·새 물리 값·언어 변경은 계속 반영한다. 전체 관측 집계·캠페인 판정을 제거하거나 갱신 시간을 늦추지는 않는다.

렌더 전송 분석은 실제 `dualSurface(createSphere(4),0)`의 크기를 사용한다. 연구 보고서의 추정 **2.52MB/갱신은 원래 구면 삼각형 수로 계산한 과소 추정**이었다. 실제 이 9개 확장 버퍼는 **7,557,120B/갱신**, 46,080개 정점이다. 연구 원문에도 정정 표기를 추가했다.

합성 staging 값을 60번 갱신한 CPU 비교에서 같은 값은 업로드 호출 540→0회, 열 색만 바꾸면 540→60회(누적 453,427,200→44,236,800B)였다. 이것은 변경 검출의 결과와 예정 전송량이다. 실제 GPU 전송·FPS 측정은 아니다. 비교 자체의 비용은 `render-uploads.json`에 있고 마지막 전송값 보관에 **7.21MiB + 해안 배열**을 쓴다. 모든 버퍼가 매번 바뀌면 전송 절감 없이 비교·복사 비용이 더해진다. 지형 staging 계산 자체와 전체 셀 진단은 아직 수행한다. 실기 결과가 불리하면 이 커밋을 되돌리거나 변경 원인별 revision으로 비교 범위를 더 줄일 수 있다.

## 6단계 — 최종 수치와 증거의 범위

### 물리 계산

최종 소스에서 162·642셀과 2,562셀 dry/wet/methane/Jupiter/기후 끈 대조군 **7개 유효 상태 해시 모두 구현 직전과 정확히 같다**. 최종 정상 평균은 wet **140.53ms**, Jupiter **183.31ms**였다. 앞 단계 139.01/183.89ms와 차이는 표본·JIT·실행 시점에 따른 변동이며, 개선율의 소수점까지 일반화하지 않는다. 같은 Mac의 Vite SSR CPU 경로이고 여전히 1× 목표 33.33ms를 넘는다.

별도 컴파일한 실제 Node Worker를 전후 같은 방식으로 비교하면 wet **100.77→88.22ms(12.5% 감소)**, Jupiter **80.42→55.84ms(30.6% 감소)**였다. 3개 배경 행성은 기존 직렬 경로 **384.63ms**, 개선한 2개 제한 동시 경로 **217.81ms**였고 완료 상태가 같다. 개선 소스 내부의 순차 299.07ms와 동시 217.81ms 비교는 약 27% 감소다. 8회 표본으로 배터리·발열·저사양 장비 경쟁까지 검증한 값은 아니다.

Node 주 스레드의 4ms timer 간격 최대값은 개선본 직접 SSR CPU wet/Jupiter **154.73/194.36ms**, Worker 사용 **5.33/5.58ms**였다. SSR 소스와 컴파일한 Worker는 실행 형태가 달라 두 처리량의 차이 전체를 Worker offload 효과로 해석할 수 없다. 이 비교는 timer에 실행 기회가 생겼다는 로컬 증거다. 브라우저의 입력 지연·Long Task·프레임 시간과는 구별한다.

### 무손실 포장 루프

전송 포장 v2의 바이트를 바꾸지 않고 루프를 JIT가 최적화할 수 있는 짧은 함수·청크로 분리했다. 29,400,632B 결정적 숫자/관측 유사 입력의 3회 중앙값은 pack **126.13→76.49ms**, unpack **97.13→58.86ms**였다. 변경 전후 SHA-256이 같고 동기/비동기 포장도 같다. 협력 실행 총 경과는 한 표본 **295.87→171.20ms**였다.

이 Node 실험의 최대 timer 간격은 오히려 **10.41→21.71ms**로 나빠졌다. GC·JSON 메타데이터·배열 할당 등 분할 밖 작업도 남아 있으므로 이 변경이 브라우저의 긴 작업을 모두 없앤다고 주장하지 않는다. 캡처·관측 장부 생성·최종 업로드 디코드의 메인 스레드 비용은 실기 프로파일로 추가 확인해야 한다.

증거 파일은 이 문서와 같은 저장소의 `docs/performance/implementation-2026-10-15/`에 있다. 빌드 그래프·전후 JSON·독립 하네스가 포함되며 생성된 대용량 프로파일과 실행 중간 결과는 무시되는 `artifacts/performance/`에 남겼다.

## 8단계 — 통합 검증·원본 보존·재현

- 전체 Vitest: **556개 통과 / 실패 0 / 조건부 19개 건너뜀**, 205.34초. 계정 실서비스 1개, 에뮬레이터 규칙 5개, 장기 기후·해상도·저장 재개 12개, 선택적 커널 감사 1개가 기본 실행에서 건너뛰어졌다. 커널 감사는 앞서 전후 비교로 별도 실행했지만, 장기 기후/실서비스/에뮬레이터까지 새로 통과했다고 쓰지 않는다. 저장 호환·최대 합성 이력·공통 수지·저온·Worker 오류·배경 참조·렌더 기하·지역화의 일반 회귀가 포함된다.
- 실제 새 저장 Worker도 Node worker_threads에서 실행했다. 2,562셀·14단계 진행 목성·모드별 4행성의 **31,331,632B** 입력을 준비한 결과는 직접 준비와 바이트가 같았다. 살아 있는 솔버 배열은 유지되고 전송용 복사만 detach됐다. 유효 입력 허용과 잘못된 activeId 거부가 확인됐다. 준비 메시지 왕복 한 표본은 144.54ms이며 브라우저 UI 시간은 아니다.
- TypeScript, 버전 검사, 격리 Vite 빌드가 통과했다. 저장소의 실제 `npm run build -- --configLoader runner`도 별도로 통과했다. Node는 설치된 **26.9.0**을 사용했으며 README의 권장 Node 24로 바꾸거나 설치하지 않았다.
- 원본의 기존 변경 **133개 경로 SHA-256**, Git 인덱스 SHA-256, 작업 상태, 브랜치 `codex/animal-ai`, HEAD `02d53d7`을 체크포인트와 비교해 모두 유지됐음을 확인했다. 별도로 진행 중인 로우폴리 수신·Cheonggye·movie-studio 작업은 수정하지 않았다.
- 이 결과는 로컬 개발 커밋이며 릴리즈가 아니다. 새 포장을 읽지 못하는 이전 앱으로 롤백하려면 이전 리비전/체크포인트를 함께 보존해야 한다. 브라우저·계정·페이지 종료 검증 전 운영 배포를 완료했다고 해석하지 않는다.

재현은 이 worktree 루트에서 기존 의존성으로 실행한다. 아래 스크립트는 합성 세계와 임시 빌드를 쓰며 사용자 브라우저 저장·실서비스 계정을 읽거나 쓰지 않는다.

```sh
node --expose-gc scripts/benchmark-performance.mjs artifacts/performance/recheck --cpu-only
node scripts/benchmark-workers.mjs artifacts/performance/recheck-workers
node scripts/benchmark-persistence-worker.mjs artifacts/performance/recheck-persistence.json
node scripts/benchmark-render-uploads.mjs artifacts/performance/recheck-uploads.json
```

검사 명령·건너뛴 항목·브라우저 차단 상태는 `verification.json`, 원본 대조는 `preservation-after.json`을 따른다. 최종 로컬 커밋 해시는 Git 기록과 전달 요약에 남긴다.
