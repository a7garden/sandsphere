# 공통 법칙 엔진 통합

2026-10-14, 개발 버전 `0.7.0-alpha.7`. 아래 alpha.6 결과와 후속 확장을 구분한다.

## 실제 실행 구조

지표의 실행 순서는 CPU·WebGPU 모두 다음과 같다.

```text
공통 시간 분할
 → prepareSurfaceStep: 대기 표시 합계 분리, 도구 입력과 외부 열 기록
 → CPU 또는 GPU의 지표 수송
 → finishSurfaceStep: 공통 반응, 생물 이동, 지표/대기 결합
 → 완료 상태 발행
```

`model.ts`의 `react`가 두 백엔드의 상변화·제작·탈출을 실행한다. 생태는
`ecology.ts`의 공통 반응망에서 실행하고 각 저장고가 총 에너지로 온도를 복원한다.
`physics.wgsl`의 별도 도구 입력·반응 구현을 제거했다. GPU는 수송을 계산하고
수송 반올림만 읽어오며, 나머지 진단은 공통 실행 코드가 기록한다. Worker도
같은 CPU/GPU 클래스를 실행한다. GPU에서 대기를 독립적으로 푸는 구조는 아니다.

원래 매 단계 수행하던 상태 읽기를 그대로 이용한다. GPU 결과를 공통 반응으로
마무리한 뒤 다시 업로드하므로, 기후를 끈 옛 경로에도 호스트 반응과 업로드 비용이
발생한다. 기후를 켠 경로는 기존에도 호스트 대기 계산과 업로드를 수행했다.

| 공통 코드 | 연결된 실제 과정 |
| --- | --- |
| `thermodynamics.ts` | 비열·상·화학 에너지 정본, 상변화 비용, 온도 복원, 위치/운동 에너지, 유한 저장고 사이 열 교환 |
| `physicsShader.ts` | 위 물성 표로 GPU 열용량·열용량 변화·운반 열 계수를 생성 |
| `conservativeTransport.ts` | 두 대기의 종별 재고 전달, 열과 접선 운동량 전달, 구면 벡터 이동, 혼합 후 속도 복원; 깊은 대기·해류의 총 유출 제한 |
| `phaseEquilibrium.ts` | 저장 대기층과 상승 진단 공기의 물 상평형, 깊은 대기 다성분 상평형의 엔탈피 해법 |
| `materialReaction.ts` | 제작·먹이망·씨앗·일괄 탄소 순환의 질량 수지 선언과 반응물 제한 |

두 대기의 층 수·저장 배치·경계는 유지한다. 일반 대기의 먼지는 기존 별도
배열을 통해 같은 종별 전달 연산에 참여한다. 두 계산기를 파일 하나로 합치거나
서로 다른 격자에 같은 압력 근사를 강제하지 않았다.

## 제거하거나 바꾼 규칙

- 물 포화압은 지표·일반 대기·깊은 대기가 `waterPhysics.ts`의 같은 식을 쓴다.
  암모니아는 별도 물성 곡선을 사용한다. 물/얼음의 융해 구간은 같은 증기 재고에서
  잠열을 분배한다. 상평형 범위 밖 에너지는 온도를 몰래 고정하지 않고 오류로 보고한다.
- 승화·구름 증발의 에너지 제한은 최저 허용 온도에서 물성 표로 계산한다.
  예를 들어 얼음→증기의 상 에너지 차이는 0°C에서 2,809kJ/kg이지만,
  −100°C에서의 전환 비용은 비열 차이까지 포함한 2,819kJ/kg이다.
- 깊은 대기 초기 온도·제트·구름 띠 선택은 `planetCreation.ts`의 생성 입력이다.
  실행 계산기는 `preset` 이름을 읽지 않는다. 기존 초기 제트와 띠는 선언한
  실험 조건으로 유지하며, 이후 원래 무늬로 복구하지 않는다.
- 단일 저장고 경로의 위도별 처방 바람을 제거했다. 운동량 상태가 없는 이
  경로에서는 구름을 대칭 확산으로 혼합한다. 자전만 바꿔 구름 무늬를 강제로
  만들지 않는다. 층별 대기에서는 압력·열 구동과 코리올리 항이 바람을 결정한다.

## 저장 호환성

셀은 36필드, 행성 스냅샷은 버전 8, 일반/깊은 대기 저장 버전은 각각 3/2를
유지한다. 새 물리 규칙을 적용하기 위해 저장에 추가 재고나 가짜 열을 넣지 않는다.
기존 1–7 버전, 16/20/24/28/32필드의 읽기와 복사 기반 업그레이드를 유지한다.
저장·계정 검증 규칙과 용량 제한도 변경하지 않았다.

로드 직후의 재고·온도·진행 시간·대기 상태를 보존하는 것과 예전 버전의 미래
궤적까지 고정하는 것은 구분한다. 공통 포화압, 구름 확산과 에너지 제한을
적용한 뒤의 궤적은 이전 엔진과 달라질 수 있다. 변경된 엔진 안에서 동일한
저장 재개와 동일한 실행 조건은 같은 결과를 내야 한다.

## 남아 있는 모델의 범위

일반 대기는 통계적 구름과 분광/회색체 복사, 깊은 대기는 다성분 포화와 회색체
복사를 사용한다. 공통 보존 법칙 위의 서로 다른 근사이며 관측으로 교정된
하나의 전 행성 기후 모델로 바뀐 것은 아니다. 격자·시간 수렴과 장기 기후 검증은
기존 검사 범위와 아래 실행 결과를 넘겨 해석하지 않는다.

생태는 유한한 일괄 탄소·생물량 전환이다. alpha.7은 재료별 화학 에너지와
흡수 일사량 제한을 추가했지만 산소·원소별 화학량론을 추적하지 않는다.
실제 광합성·연소·메탄 생성의 화학식을 재현한다고 설명하지 않는다.
지표의 기반 열용량, 제작 온도·시간, 토양 보수력, 운동량을 저장하지 않는
얕은 해류, 수치 온도 범위도 명시적인 기존 근사로 남는다.

무늬 없는 초기 상태의 단기 대조 실험은 흐름이 국소 열 구동에서 시작됨을
검사한다. 실제 목성의 제트나 띠가 자발적으로 형성된다는 정량 검증은 아니다.

## alpha.7 — 파우더 토이형 재료 반응

`ecology.ts`의 `reactEcosystem`이 단일/층별 대기의 먹이망과 재료 반응을
함께 실행한다. 재료와 국소 조건으로 경로를 고르며 장면·과제·행성 이름은
반응에 관여하지 않는다. `soil`은 유기물 재고이지 모든 광물 토양이 아니다.
새 산소 재고나 무한한 주변 산소를 가정하지 않는 일괄 탄소 게임 모형이다.

| 조건 | 재고 이동 | 에너지 처리 |
| --- | --- | --- |
| 식생/씨앗 + 빛 + 수분 + 탄소원 | CO₂ 또는 유기물 → 식생 | 흡수 단파의 최대 25%를 화학 에너지로 저장 |
| 초식/포식 + 먹이 | 먹이 → 소비자 + 유기물 | 재료 포텐셜 차이를 열로 반환 |
| 씨앗 발아·생산 | 씨앗 ↔ 식생 | 같은 화학 에너지의 재배치 |
| 쇠퇴·익사 | 생물량 → 유기물 | 화학 에너지 차이를 열로 반환 |
| 따뜻하고 젖은 유기물 | 유기물 1 → 메탄 0.25 + CO₂ 0.75 | 유한한 재고와 포텐셜 차이로 제한; 염분이 속도 억제 |
| 건조한 고온 | 생물량 → 유기물 → CO₂ | 180°C부터 열분해 속도 증가; 생성 기체는 대기로 이동 |

`CHEMICAL_ENERGY`는 CO₂=0, 유기물=0.01, 메탄=0.03,
식생·씨앗·소비자=0.05 게임 kJ/kg이다. 실제 생성 엔탈피나 생물의 에너지
밀도가 아니다. `MATERIAL_ENERGY = PHASE_ENERGY + CHEMICAL_ENERGY`이며,
엔탈피·공급·수송·회수·탈출이 같은 표를 사용한다. 물 상평형과 상승 공기 계산은
반응하지 않는 건조 기체의 화학 에너지를 열로 오인하지 않도록 분리한다.

광반응은 이미 에너지 장부에 기록된 흡수 단파를 나눠 쓴다. 추가 외부 에너지를
기록하지 않으며, 사용하지 않은 몫은 열로 남는다. 반응 후 총 에너지에서 새
재료 포텐셜을 빼 온도를 복원한다. 작은 반응량이 Float32 반응물에서 차감되지
않는데도 생성물만 늘어나는 경로를 차단했다.

`climateUnits.ts`는 단일/층별 대기의 일사 에너지 환산을 공유한다. 단일 모드의
주변 열욕은 명시적인 외부 경계이고, 햇빛은 별도 유한한 에너지 입력이다.
구름을 위한 숨은 −12°C 저장고는 없다. 대기층 모드는 실제 층 온도와 운동으로
구름을 만든다. 얕은 해류는 보존적인 재료·열 수송을 위한 운동학적 근사로 남고,
해양 운동에너지나 완전한 해양 역학을 추가한 것은 아니다.

저장에 새 누적 에너지를 쓰지 않는다. 기존 재료의 성질로 화학 에너지를
해석하므로 로드 시 재료·온도·시간·대기 배열을 바꾸지 않는다. 새 엔진의 이후
궤적은 달라진다. 과거 관측 엔탈피는 재작성하지 않고, `chemicalEnergy`가 없는
옛 관측과 새 관측 사이에는 에너지 수지를 계산하지 않는다. 대시보드에서 새
관측 기준을 잡으면 새 기준의 수지를 볼 수 있다. 이전 CSV와 저장도 계속 읽는다.

`tests/ecochemical-laws.test.ts`는 광자/반응물 제한, Float32 한계, 무광·건조·
고염분·생명/탄소원 부재 대조군, 습윤/열분해, 반응 순환 에너지, 실제 온도의
구름, 기체 생성→적외선 피드백, 단일/층별 수지와 JSON 재개를 검사한다.
캠페인 검증은 8kg 식생을 빛이 드는 여러 셀에 나눠 놓고 명시적인 물·열 도구로
조건을 유지해 식생 9kg과 초식 4.2kg 목표를 확인한다. 과거의 무제한 3초 성장
경로는 유지하지 않는다.

## 산소·원소 반응 확장 (alpha.8)

이 절은 위 alpha.6/alpha.7의 당시 결과를 대체하는 현재 반응 정의다.
파우더 토이형 재료 실험을 위해 식생·씨앗·소비자·유기물은 모두 경험식
CH₂O로 나타낸다. 원소 표의 정수 게임 원자량 H=1, C=12, O=16을 사용한다.
이는 동위원소·개별 생체분자·불완전 연소를 풀어내는 화학 패키지가 아니다.
기존 기압/복사의 이상기체 분자량·분광 표는 근사 물성으로 유지한다.

| 공통 반응 | 원소별 화학량론 | 조건 |
| --- | --- | --- |
| 광합성 | CO₂ + H₂O → CH₂O + O₂ | 실제 식생/씨앗, 물·CO₂, 흡수 일사 |
| 발효 | 2 CH₂O → CH₄ + CO₂ | 따뜻하고 젖은 유기물, 낮은 산소; 염분 억제 |
| 호흡·유기물 연소 | CH₂O + O₂ → CO₂ + H₂O | 생물학적 온도 창의 느린 호흡 / 250°C 이상 연소 |
| 메탄 연소 | CH₄ + 2 O₂ → CO₂ + 2 H₂O | 500°C 이상 |
| 발아·유기물 흡수·섭식·쇠퇴 | 같은 CH₂O 재고의 재배치 | 서식·먹이 조건 |

`chemistry.ts`의 조성과 `stoichiometricReaction`이 몰 계수를 질량 계수로
컴파일하고 원소/질량 불균형을 거부한다. 광물도 불활성 경험식을 선언한다.
점토 소성은 원소 조성을 유지하는 구조 변화 근사이며 탈수 반응은 추가하지 않았다.
새 재료 반응은 여기에 조성과 계수를 등록하고 기존 재고·열 수송에 연결한다.
장면 이름이나 미션 상태로 산소·열·생성물을 발생시키는 분기는 없다.

화학 포텐셜은 CH₂O=4500, CH₄=16000 게임 kJ/kg이고 CO₂/H₂O/O₂=0이다.
따라서 유기물 1kg의 발효는 233.333 게임 kJ를, 완전 산화는 4500을 방출한다.
메탄 1kg의 산화는 액체 물 기준 16000을 방출한다. 물이 수증기가 되는 데는
기존 공통 상 에너지 비용을 별도로 지불한다. 입력 광에너지 없이 반응 순환으로
새 에너지를 만들 수 없다. 숫자들은 게임 물성으로, 실제 반응열·점화점 측정값이 아니다.

흡수 일사는 기존 환경 장부에 한 번만 들어온다. 식생이 있는 셀은 그중 25%를
유한한 광 여기 에너지로 보관한다. Float32 차감/생성이 모두 표현되는 반응만
진행하며 명목 반응 비용과 실제 반올림된 화학 에너지 증가 중 큰 값을 지불한다.
남은 여기 에너지는 게임 시간 기준 0.01/s로 열로 완화된다. 반응 후 현열·상·화학·
광 에너지의 합을 보존해 온도를 복원한다. 기존 물질에 큰 반응열을 부여한 만큼
옛 포텐셜로 기록한 관측과는 기준을 분리한다.

지표와 최하층 기체가 접촉한다. 상층 기체는 수송되어 내려와야 지표 반응에 쓰인다.
각 대기층의 메탄 산화는 그 층의 유한한 산소와 실제 온도를 사용한다. 생긴 물·
CO₂·열이 일반 응결·강수·증발·복사·압력·열전도로 이어진다. 유기물 연소가 메탄을
점화하고 생성된 물이 증발하는 조합은 전용 연출 분기 없이 같은 계산에서 나온다.
반응으로 2400°C를 넘길 연료는 남겨 두고, 더 높은 상태에 대한 기존 모델 범위
진단은 유지한다. 깊은 수소·헬륨 대기는 이번 산소 반응 대상에 포함하지 않는다.

## 불완전 연소와 열분해 — 0.7.0-alpha.9

### 공통 반응과 에너지

유기물·생체량은 CH₂O, 숯은 순수 C, 일산화탄소는 CO로 표현한다.
모든 경로는 `stoichiometricReaction`이 원소와 질량 수지를 검사한 뒤,
`reactInventory`가 가장 부족한 반응물까지 반응량을 제한한다.

| 경로 | 몰 반응식 |
| --- | --- |
| 메탄 불완전 연소 | 2 CH₄ + 3 O₂ → 2 CO + 4 H₂O |
| 유기물 불완전 연소 | 2 CH₂O + O₂ → 2 CO + 2 H₂O |
| 무산소 유기물 열분해 | CH₂O → C + H₂O |
| 숯 완전/불완전 연소 | C + O₂ → CO₂ / 2 C + O₂ → 2 CO |
| CO 재산화 | 2 CO + O₂ → 2 CO₂ |

완전 연소에 필요한 산소량 대비 현재 재고 비율을 `r`이라 하면 완전 경로 비중은
`clamp(2r−1,0,1)`, 나머지는 불완전 경로다. 한 단계의 소모 예정량 대신 실제
연료 재고를 기준으로 삼아 시간 간격만 줄인다고 완전 연소로 바뀌지 않는다.
산소가 없으면 산화는 멈추며, 유기물 열분해는 산소 부족도와 온도로 속도가 정해진다.
열분해 기준은 300°C, 숯·CO의 산화 기준은 350°C다. 기존 유기물 250°C·메탄
500°C 기준은 유지한다. 모두 파우더 토이형 게임 반응 속도·점화 기준이다.

새 화학 에너지는 C=12000, CO=4000 게임 kJ/kg이다. 기존 물질의 값은 바꾸지
않는다. 액체 물 기준 CH₂O 1kg의 열분해는 화학 에너지 300을 저장하며 현열을
소비한다. 열용량 변화와 이후 증발 비용도 같은 엔탈피에 포함한다. 열분해 후
숯 산화까지의 총 에너지 변화는 직접 완전 연소와 같고, CO를 거치는 경로도
동일하다. 연료마다 반응열을 별도 덧셈하지 않으며, 새 생성물은 다음 국소 반응의
실제 재고가 된다. 숯의 열로 인접 계산 단계에서 메탄 점화가 시작되는 조합도 검사한다.

`thermalReactionLimit`은 반응 전후 물성으로 열 예산을 검사한다. 열분해가
300°C 아래까지 현열을 소비할 양은 실행하지 않고, 2400°C를 넘길 산화량도
실행하지 않는다. 에너지를 잘라내는 대신 반응물을 남긴다. 반올림 오차는 기존
수치 채널에 드러내며, 닫힌 반응기 검사는 그 보정 없이 전체 엔탈피를 비교한다.

### 재고·표시·저장

- 슬롯 34=C, 35=CO. 셀 폭 36과 명령 폭 20을 유지한다. 숯은 지표에 남는 고체로
  질량·열용량·열전도·반사율·높이·지표 지우기에 포함한다. CO는 기체 확산·층간
  수송·기압·수증기 포화·열용량·우주 탈출에 포함한다.
- 지표 숯은 접한 최하층 산소만 소비한다. 대기층의 메탄과 CO는 그 층의 온도와
  산소로 반응한다. 대기 반응은 지표에서 중복 실행하지 않는다.
- 저장 v10, 대기 v5(8종). 대기 v4의 7종과 v1–v3의 6종을 정확한 폭으로 읽어
  CO를 마지막에 0으로 붙인다. 저장 v1–v9에는 예약 슬롯의 비영 값이 허용되지
  않는다. 이전 재료·온도·시간과 원본 JSON을 변경하지 않는다.
- `chemistryVersion=2` 유지: 기존 물질의 에너지 기준이 같고 옛 저장의 C/CO는
  0이므로 이전 관측과 에너지 차이를 비교할 수 있다. 새 관측 열을 갖지 않은 CSV와
  관측 저장은 숯·CO·CO 몰 분율을 미관측(null)으로 보존한다.
- 숯 색·깊이 구성·지점 물질량과 CO의 대기 질량·몰 분율·대시보드를 표시한다.
  숯·CO는 현장에서 기존 재료를 반응시켜 만드는 재료이며 공급/회수 상품은 아니다.

이는 축약된 게임 화학이다. 타르·라디칼·수소 생성, 메탄의 그을음 경로, 숯 입자의
공중 부유·분립 이동·광학 연기와 CO 분광 복사는 아직 모델링하지 않는다. CO는
열역학·유체역학에 참여하는 비응축 기체이며 별도 적외선 흡수 계수는 없다.
깊은 수소·헬륨 대기는 이 산소 반응망의 적용 대상이 아니다.

## 0.7.0-alpha.10 — 이동하는 탄소와 연기

### 같은 재고로 이어지는 과정

구형 파우더 토이의 재료 실험을 위해 다음 경로를 연결했다. 열·산소·바람에
반응하는 것은 실제 C 재고다. 연기 연출이 별도의 물질이나 연소 에너지를
공급하지 않는다.

```text
유기물 + 열 → 숯 + 미세 탄소 + 물
산소가 매우 부족한 메탄 + O₂ → 미세 탄소 + 물
숯 → 경사에 따른 이동 → 바람 비산 → 대기 수송 → 침강 → 숯
공중 미세 탄소 + O₂ → CO / CO₂ + 열 → 다른 반응·상변화
공중 미세 탄소 → 복사 흡수·산란 변화 → 열과 기류 변화
```

- 지표 숯(34)과 공중 그을음(36)은 같은 C 조성, 비열 0.71, 화학 에너지
  12000 게임 kJ/kg을 쓴다. 미세 탄소는 기체 몰수에는 포함하지 않고 층의
  질량·열용량·하중·운반 에너지에는 포함한다.
- `CH₄ + O₂ → C(그을음) + 2 H₂O`를 선언했다. 완전 연소 산소 요구량 대비
  재고 비율 `r`에 대해 완전 경로는 `clamp(2r−1,0,1)`, 그을음 경로는
  `clamp(1−2r,0,1)`, 나머지는 CO 경로다. 실제 산소가 없으면 산화는 멈춘다.
- 열분해는 `CH₂O → 0.8 C(숯) + 0.2 C(그을음) + H₂O`다. 80/20 분할은
  게임의 입자 크기 근사다. 두 형태의 에너지 기준이 같아 이전 반응의 총
  화학 에너지를 바꾸지 않는다. 생성된 공중 탄소도 숯과 같은 완전/불완전
  산화 선언과 350°C 게임 점화 기준을 사용한다.
- 숯의 지표 흐름은 기존 유한 재고 경사 수송에 연결했다. CPU와 WGSL은 같은
  한 단계 유출 제한을 적용하고 물질의 현열을 함께 운반한다. 지표 분립 흐름은
  기존 모래와 같이 별도 고체 운동량·지형 위치 에너지를 저장하지 않는 근사다.
- `aerosolPhysics.ts`의 바람 응력·피복·유한 재고 비산, 압력·온도·중력에 따른
  침강 법칙을 먼지와 그을음에 공통 적용한다. 그을음은 유효 반지름 2μm,
  밀도 1500kg/m³의 게임 입자다. 지표는 비산의 위치 에너지를 지불한다.
  정지 입자의 유입은 바람의 운동량을 희석하고 잃은 운동 에너지는 열로 남는다.
  대기층끼리 침강할 때 운동량을 섞으며, 지표 침전의 운동량은 고정 지표가
  받는다. 침전 에너지는 지표 열에 포함한다.
- Float32 지표에서 표현할 수 없는 미량은 새 탄소로 반올림하지 않는다.
  비산 수요는 누적하고, 침전 불가능한 양은 Float64 대기에 남긴다. 바닥층에서
  미량이 남아도 윗층의 침강은 계속한다. 지표 반응의 기체·그을음 교환도
  유출 운동 에너지와 정지 생성물의 운동량 혼합을 같은 장부에 포함한다.
- 층별 대기는 같은 수송기를 이용한다. 단순 모드는 기존 확산과 공통 침강을
  사용하며 별도 바람장·층별 복사 피드백은 계산하지 않는다. 층별 복사에는
  그을음의 회색 흡수·산란을 연결한다. 먼지와 그을음의 산란 비율이 다르므로
  복사 캐시는 두 재고의 변화를 각각 추적한다.
- 화면은 실제 탄소량과 질량 가중 높이를 압축한 기둥 투영이다. 공중 탄소가
  없으면 연기도 없다. 입자 하나씩의 모양이나 난류 소용돌이를 해상하지는 않는다.

### 연결된 과정과 에너지 처리

지표의 연소·열분해와 실제 대기층의 산화를 대기 적분의 짧은 단계마다

포함하는 가상 온도를 사용한다. 지표의 미해상 자연대류는 같은 공기 조성에서
표면/공기 온도 차이로 교환 속도를 `sqrt(max(1,u²) + max(0,b) × z)`로
계산한다. 이 속도는 열·수분 교환 계수이며 별도 운동 에너지 재고가 아니다.
양쪽 열용량으로 제한한 교환량만 지표에서 빼고 공기에 더한다. 오프라인
기후 실험의 명시적 풍속 경계 조건은 기존 지정 계수를 그대로 사용한다.

보존하여 생성물의 화학·현열·위치 에너지와 운동량 혼합 비용을 처리한다.

지표의 대기 합계 필드는 실제 층별 재고와 중복 계산하지 않는다.

## alpha.12 — 저온 에너지 해와 기존 메탄 저장 재개 (2026-10-15)

### 원인: 초기 기후 범위를 에너지 해의 하한으로 사용

alpha.11에서 남긴 실제 v11 저장을 브라우저에서 읽어 로컬 복사본으로 검사했다.
2562셀, 약 514물리시간 진행 상태다. 원본 파일과 브라우저 저장은 수정하지
않고 재현했다. 변경 전에는 세 번째 1/30게임초 단계에서 셀 1092, 대기층 4가
−150.032380952°C가 되어 상평형 계산이 중단됐다.

문제 층의 과정을 분리하면 첫 압력 가속에서 운동 에너지는
0.010139435353 모델 kJ 증가하고, 온도는 0.064678201°C 낮아진다.
층의 총 에너지 변화는 2.28×10⁻¹³ kJ 미만이다. 이후 수평/수직 수송과
운동량 혼합은 일부를 다시 열로 돌려준다. 복사나 연소로 설명되지 않는
에너지 유출은 이 실패 경로에서 발견되지 않았다. 실패 시점에도 절대영도
기준 현열 `C × (T + 273.15)`는 약 19.2541 kJ로 양수였다.

기존 코드는 초기 프로필의 −150°C(얇은 CO₂ 대기는 −220°C)를 저장 메타데이터,
상평형 역산, 강수 증발 제한 및 최종 상태 검사에 함께 사용했다. 따라서
에너지 장부가 허용하는 해를 프로필 범위가 거부했다. 온도를 −150°C로 되돌리면
새 열을 만들어야 하므로 그러한 보정을 넣지 않는다.

### 변경된 공통 계약

- `thermodynamics.ts`의 공통 수치 영역은 양의 켈빈 온도다. 기존 진단 공기
  덩어리 해법이 사용하던 −273.14°C(0.01K)를 공통 상수로 정의했다. 이 값은
  유효성 검사와 엔탈피 해의 구간 끝이며, 계산 후 온도를 잘라 맞추는 값이 아니다.
- 저장된 실제 대기층의 상평형도 진단 공기 덩어리와 같은 구간에서 같은
  `H(T)`를 푼다. 종별 비열·상 에너지·화학 에너지와 압력 가속, 마찰 및 수송
  법칙은 유지한다. 새로운 열 공급이나 수지 보정은 추가하지 않는다.
- 강수의 재증발·승화는 같은 구간에서 지불할 수 있는 잠열과 유한한 강수량,
  포화 조건으로 이동량을 제한한다. 미지불 열을 더하거나 물을 생성하지 않는다.
- 저장 및 실행 검증도 같은 열역학 구간을 사용한다. 에너지가 구간 밖이거나
  값이 비유한이면 계속 오류를 내고 상태·장부를 원자적으로 되돌린다.
- `minTemperature` 필드는 기존 초기 프로필/지표 경계 선택의 메타데이터로
  유지한다. 저장 v11, 대기 v6, 재고 폭, 화학 에너지 기준을 바꾸지 않는다.
  기존 저장의 재고·온도·시간을 재작성하지 않고, 이후 −150°C 아래로 진화한
  대기 상태도 그대로 저장하고 재개한다. 구형 앱에서 새 저온 상태까지
  읽을 수 있다는 순방향 호환성을 주장하지는 않는다.

원래 진단용 저장 복사본은 별도로 보존했으며, 로컬 앱의 정상 진행·자동 저장과
원본 복사본을 이용한 수지 감사를 구분한다.

전체 회귀 검사는 **536개 통과, 조건부 19개 건너뜀**(75개 파일 통과,
8개 건너뜀, 282.05초)이다. 실제 저장을 지정하는 별도 장시간 감사는
환경변수를 주어 따로 실행한다. 저온 6개와 화성 16개 관련 검사는 별도로
22개 모두 통과했다. `npm run check:version`, `npm run build` 및
`git diff --check`도 통과했다. 빌드의 기존 대형 청크 경고는 유지되며,
릴리즈 발행이나 운영 배포는 수행하지 않았다.

### 실제 514시간 메탄 저장의 추가 600단계 감사

`tests/methane-save-resume.test.ts`로 원래 오류를 재현한 2562셀 저장을
600단계, 20게임초(20물리분) 더 계산했다. 매 단계 실제 궤도·자전을 갱신한다.
중간에는 저온 상태를 JSON으로 읽고 다음 단계의 재고·온도·바람·캐시를
원본 실행과 대조했다. 최종 저장도 유효하며, 입력 파일의 바이트와 SHA-256은
실행 전후 동일했다. **별도 감사 1개 통과**, 1003.33초다.

| 항목 | 결과 |
| --- | ---: |
| 초기 실제 재고 | 35504.7965273 모델 kg |
| 초기 총 에너지 | 20701209.3397 모델 kJ |
| 추가 진행 중 최저 / 최고 대기 온도 | −151.884707 / 186.060704°C |
| 최종 질량 잔차 (기체 탈출 포함) | +0.01274548 모델 kg, 초기의 3.590×10⁻⁷ |
| 원소별 최대 정규화 잔차 | 1.304×10⁻⁶ |
| 외부·수치 채널 분리 후 에너지 잔차 | 최종 −2.016×10⁻⁸ 모델 kJ, 집계 지점 최대 8.831×10⁻⁸ |
| 별도 누적 수치 채널 | −8.668093 모델 kJ, 초기 에너지의 4.188×10⁻⁷ |
| 중간 JSON 재개 / 최종 저장 / 입력 원본 보존 | 모두 통과 |

질량은 표시용 대기 합계 대신 실제 Float64 층 재고와 Float32 지표 재고로
계산한다. 원소별 정규화는 `|변화 + 탈출| / max(1, 초기 원소 재고)`다.
질량·원소 허용치는 2×10⁻⁶, 에너지 장부 잔차는 초기 에너지 대비 10⁻⁹,
수치 채널 자체는 초기 에너지 대비 10⁻⁵로 검사했다. 최저 온도가 마지막
구간에서도 변하므로 평형 도달을 주장하지 않으며, 관측한 600단계의 안정성과
작은 격자 10,000단계 검사를 각각 보고한다.

로컬 재실행용 원본과 결과는 Git에서 제외된
`artifacts/methane-resume/input.snapshot.json`, `report.json`에 보존했다.
원본 해시는 `fcb6978b1e0aa1794a2af6774f538f7cf0d64f6c7a63597de809eca74f8b5d3a`다.
다음 명령은 브라우저 저장이나 입력 파일을 쓰지 않는다.

```sh
METHANE_SAVE_PATH=artifacts/methane-resume/input.snapshot.json METHANE_STEPS=600 \
  npx vitest run tests/methane-save-resume.test.ts --maxWorkers=1 --disableConsoleIntercept
```
